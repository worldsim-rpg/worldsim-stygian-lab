# 04. Интерфейс

Нормативная спецификация UI прототипа «Стигийская библиотека» (соло depth crawl,
один файл `index.html`, vanilla JS + SVG + CSS, без внешних ресурсов).
Все значения в этом документе обязательны к реализации точно как написано.
Эмодзи запрещены везде. Иконки — только SVG-примитивы или буквы.
Нативные диалоги браузера (`alert`, `confirm`, `prompt`) запрещены.

---

## 1. Экраны

Приложение состоит из четырёх экранов. Каждый экран — корневой `div`
(`#screen-start`, `#screen-game`, `#screen-win`, `#screen-lose`). Видимость
переключается классом `is-active` (видимый: `display: flex`; остальные:
`display: none`). Одновременно виден ровно один экран. Модальных окон нет.

### 1.1. Экран `start`

Вертикальная колонка по центру окна, `max-width: 560px`, выравнивание по центру.
Содержимое сверху вниз:

1. Заголовок «Стигийская библиотека» (36px, флейворный шрифт, цвет `--accent-gold`).
2. Подзаголовок «Соло-прототип depth crawl по мотивам The Stygian Library»
   (15px, UI-шрифт, цвет `--text-muted`).
3. **Блок продолжения** — рендерится только если в `localStorage` есть автосейв:
   - заголовок блока «Найдена сохранённая партия» (11px, верхний регистр);
   - строка-сводка по шаблону «Seed {seed} · ход {turn} · глубина {depth}»
     (13px, `--text-muted`);
   - кнопка «Продолжить партию» (primary, на всю ширину колонки).
     Клик загружает сейв и открывает экран `game`; выбор пресета и поле seed
     при этом игнорируются.
4. Заголовок секции «Исследовательский вопрос» (11px, верхний регистр,
   `--text-muted`).
5. Три карточки-пресета (radio-поведение: выбрана ровно одна, по умолчанию —
   первая). Каждая карточка: имя (17px, флейворный шрифт) и описание
   (13px, UI-шрифт, `--text-muted`). Выбранная карточка — рамка
   `2px solid var(--accent-gold)`, остальные — `1px solid var(--border)`.
   Пресеты:

   | id пресета | Имя | Описание | Порог Progress | Мин. глубина |
   |---|---|---|---|---|
   | `easy` | «Забытый рецепт» | «Бытовое знание. Прогресс 10, глубина не менее 3.» | 10 | 3 |
   | `medium` | «Утраченная биография» | «Редкое знание. Прогресс 20, глубина не менее 6.» | 20 | 6 |
   | `hard` | «Запретный гримуар» | «Опасное знание. Прогресс 30, глубина не менее 10.» | 30 | 10 |

6. Поле seed: подпись «Seed» (11px, верхний регистр) и текстовый `input`
   (14px, UI-шрифт) с placeholder «Пусто — случайный seed». Принимается любая
   строка, обрезается до 32 символов. Пустое поле: генерируется случайное целое
   1..999999, оно становится seed и далее показывается в статусе.
   Нажатие Enter в поле эквивалентно клику по кнопке входа.
7. Кнопка «Войти в библиотеку» (primary, на всю ширину колонки). Клик:
   стирает старый автосейв, создаёт новую партию с выбранным пресетом и seed,
   открывает экран `game`.

### 1.2. Экран `game`

Раскладка — см. раздел 2. Содержит карту (SVG) и боковую панель: статус-блок,
блок текущей комнаты, контекстные кнопки действий, лог событий.

### 1.3. Экран `win`

Вертикальная колонка по центру окна, `max-width: 560px`. Сверху вниз:

1. Заголовок «Знание найдено» (36px, флейворный шрифт, `--accent-gold`).
2. Текст «Вы выбрались на поверхность с ответом на вопрос. Библиотека отпустила
   вас — на этот раз.» (16px, флейворный шрифт, по центру, line-height 1.55).
3. Блок статистики — четыре строки (15px, UI-шрифт), подпись слева
   (`--text-muted`), значение справа (`--text`):
   - «Ходов» — итоговый номер хода;
   - «Максимальная глубина» — наибольший достигнутый depth;
   - «Прогресс» — формат «{progress} / {threshold}»;
   - «Seed» — seed партии.
4. Кнопка «Новая партия» (primary). Клик: стирает автосейв, открывает `start`.

Экран `win` показывается, когда игрок при выполненных условиях победы
(Progress >= порога И максимальная достигнутая глубина >= минимальной)
переходит в узел входа (depth 0).

### 1.4. Экран `lose`

Та же структура, что `win`, с отличиями:

1. Заголовок «Библиотека забрала вас» (36px, флейворный шрифт, цвет `--danger-text`).
2. Текст «Ваши HP опустились до нуля. Где-то в глубине стеллажей появилась новая
   книга — с вашей историей.»
3. Тот же блок статистики (4 строки).
4. Кнопка «Новая партия» (primary).

Экран `lose` показывается в момент, когда HP <= 0.

  текущему состоянию; кнопка «Сдаться» (danger-стиль) присутствует всегда и
  идёт последней. См. раздел 6.
- **#log**: заголовок «ЖУРНАЛ» (11px, верхний регистр, `--text-muted`) и
  прокручиваемый список записей. См. раздел 7.

## 5. Карта: узлы, рёбра, подписи

Карта — один элемент `<svg>` фиксированной ширины **860px**, горизонтально
отцентрированный внутри `#map-pane`. Высота SVG = `(maxDepth + 1) * 96 + 48`
пикселей и увеличивается по мере открытия новых глубин. Прокрутка — только
вертикальная, средствами `#map-pane`.

**Полосы глубины.** Каждой глубине соответствует горизонтальная полоса высотой
96px (depth 0 — верхняя, рост вниз). Полоса — `<rect>` на всю ширину SVG,
заливка чередуется: чётный depth — `--bg-stripe-a`, нечётный — `--bg-stripe-b`.
В левом верхнем углу полосы (x = 12, отступ сверху 8px) — подпись
«ГЛУБИНА {N}» (11px, верхний регистр, `--text-faint`).

**Позиционирование узлов.** Центр узла по вертикали — середина его полосы.
По горизонтали полоса делится на 10 слотов шириной 86px; допустимые X —
центры слотов (43, 129, 215, ... 817). Новый узел занимает свободный слот,
ближайший по X к родительскому узлу (при равенстве — левый). Узел входа
(depth 0) всегда в слоте 5 (x = 387). Назначенная позиция никогда не меняется —
узлы не передвигаются. UI рассчитан максимум на 10 узлов одной глубины;
генерация не должна создавать больше.

**Открытый узел (комната).** `<g>` со структурой:

- невидимый хит-круг `r = 22`, `fill: transparent` (зона клика);
- основной круг `r = 16`, заливка — цвет тега локации (см. таблицу палитры),
  обводка `1px` цвета `--border`;
- буква тега по центру круга (13px, bold, UI-шрифт, цвет `#16120e`);
- подпись — краткое имя комнаты **всегда видно** под узлом (y = центр + 30,
  по центру, 11px, `--text-muted`; для текущей комнаты — `--text`).
  Имя обрезается до 14 символов с многоточием. Подписи по hover НЕ используются,
  `<title>`-тултипов нет.

Кодировка тегов (цвет + кириллическая буква внутри круга):

| Тег (id) | Буква | Смысл | Цвет |
|---|---|---|---|
| `entrance` | В | вход в библиотеку | `--node-entrance` `#c9a227` |
| `hall` | З | залы, фойе, читальни | `--node-hall` `#6f8f5a` |
| `stacks` | Х | хранилища, стеллажи, архивы | `--node-stacks` `#a98e5e` |
| `service` | С | служебные и технические места | `--node-service` `#5e7d8c` |
| `dweller` | Ж | обитаемые места, гнёзда, кельи | `--node-dweller` `#8c6e9c` |
| `anomaly` | А | аномальные и невозможные места | `--node-anomaly` `#a04048` |

Каждая из 30 строк таблицы локаций имеет ровно один тег из пяти
(`hall`/`stacks`/`service`/`dweller`/`anomaly`); тег `entrance` — только у входа.

**Заглушка (неисследованный выход).** Круг `r = 16`, `fill: none`, пунктирная
обводка `stroke: var(--node-stub); stroke-width: 1.5; stroke-dasharray: 4 3`,
в центре знак «?» (14px, UI-шрифт, `--node-stub`). Подписи под заглушкой нет.
Хит-круг `r = 22` тот же.

**Текущая позиция игрока.** Отдельный маркер — `<g id="player-marker">`
с кольцом `r = 21`, `fill: none`, `stroke: var(--ring-current)`,
`stroke-width: 2.5`. Маркер один на всю карту и перемещается на центр
текущего узла (см. анимации, раздел 8).

**Посещённые узлы.** Узлы, в которых игрок уже был, но которые не являются
текущими: заливка основного круга с `fill-opacity: 0.55` (буква и подпись без
изменений). Текущий узел — `fill-opacity: 1`.

**Рёбра.** Линия `<line>` от центра к центру, `stroke: var(--edge)`,
`stroke-width: 2`. Ребро, ведущее к заглушке, — то же, но пунктиром
`stroke-dasharray: 4 4`. Рёбра рисуются под узлами (раньше в DOM).

## 6. Взаимодействие

Единственное устройство ввода — мышь. **Клавиатурное управление в игре
отсутствует и не реализуется** (намеренно вычеркнуто: у point-crawl графа
переменное число соседей, стрелочная навигация неоднозначна). Единственное
исключение — Enter в поле seed на экране `start` работает как клик по
«Войти в библиотеку» (бесплатно через обработчик keydown).

Правила кликов по карте:

1. **Доступный узел** = узел (открытый или заглушка), соединённый ребром с
   текущим узлом. Клик по нему — переход:
   - в заглушку: генерируется комната (броски по таблицам), заглушка
     заменяется открытым узлом, добавляются её новые заглушки-выходы;
   - в открытый узел: обычное перемещение, комната не перегенерируется.
2. При наведении на доступный узел: курсор `pointer` и подсветка — кольцо
   `r = 20`, `stroke: var(--accent-gold)`, `stroke-width: 2`, появляется
   за 100ms (CSS transition по opacity). Подсветка снимается при уходе курсора.
3. **Недоступные узлы** (не соседи текущего) не реагируют ни на hover, ни на
   клик: курсор обычный, подсветки нет, обработчик игнорирует событие.
4. Клик по текущему узлу игнорируется.
5. На время ничего не блокируется: переходы мгновенны в логике, анимация
   маркера чисто косметическая, дополнительные клики во время неё допустимы.

Контекстные кнопки действий в `#actions`:

- список кнопок формирует игровая логика из текущего состояния (например,
  «Осмотреться», «Отдохнуть»); максимум 4 кнопки, каждая на всю ширину блока;
- недоступные в данный момент действия не показываются вовсе (не disabled);
- кнопка «Сдаться» (danger) есть всегда и стоит последней.

Подтверждение «Сдаться» — инлайн, без модалок: по клику содержимое блока
`#actions` заменяется на текст «Покинуть партию? Сохранение будет удалено.»
(13px, `--text-muted`) и две кнопки: «Да, сдаться» (danger) и «Отмена»
(обычная). «Да, сдаться» стирает автосейв и открывает экран `start`;
«Отмена» возвращает прежний список действий. Сдача — не поражение: экран
`lose` показывается только при HP <= 0.

## 7. Лог событий

Лог хранит и показывает **последние 50 записей** (массив в состоянии игры
ограничен 50 элементами, старые отбрасываются; лог входит в автосейв).
Новые записи добавляются вниз; после каждой записи контейнер прокручивается
в самый низ безусловно (`el.scrollTop = el.scrollHeight`).

Формат записи — одна строка-блок:

```
{номер хода} | {текст}
```

- номер хода — фиксированная колонка 32px, выравнивание вправо,
  цвет `--text-faint`;
- текст — 13px, UI-шрифт, цвет `--text`;
- блок записи: `padding: 4px 8px`, левая рамка `3px solid` цвета типа,
  отступ между записями 2px.

Типы записей и их цвет (цвет применяется к левой рамке; текст остаётся
`--text`, кроме типа `system`, у которого и текст `--text-muted`):

| Тип (id) | Цвет рамки | Что логируется |
|---|---|---|
| `combat` | `--danger-text` `#d07a6a` | атаки, полученный и нанесённый урон, итоги боя |
| `find` | `--accent-gold` `#c9a227` | найденные книги, предметы, сокровища |
| `progress` | `--success` `#7fa05a` | изменения Progress, достижение порога, выполнение условия глубины |
| `system` | `--text-muted` `#8a7c66` | переходы между комнатами, открытие новых комнат, начало партии, сохранение, отдых |

Каждая запись игровой логики обязана указывать один из этих четырёх типов.

## 8. Анимации

Разрешены **только CSS transitions длительностью не более 300ms**.
`requestAnimationFrame` для игрового цикла запрещён; игрового цикла нет вообще —
всё событийно (клики). JS-таймеры допустимы только как технический трюк
для снятия стартового CSS-класса (см. ниже).

Нормативный список анимаций (других не делать):

1. **Появление нового узла** (открытая комната или заглушка): элемент
   добавляется с классом `is-new` (`opacity: 0; transform: scale(0.6)` с
   `transform-origin` в центре узла, `transform-box: fill-box`), через
   `setTimeout(..., 20)` класс снимается; transition
   `opacity 250ms ease-out, transform 250ms ease-out`.
2. **Перемещение маркера игрока**: `#player-marker` позиционируется через
   `transform: translate(x, y)` (атрибут style), CSS:
   `transition: transform 300ms ease-in-out`.
3. **Hover-подсветка доступного узла**: кольцо с `transition: opacity 100ms`.
4. **Hover кнопок**: `transition: background-color 120ms`.
5. **Появление экрана**: активный экран получает класс с
   `opacity: 0 -> 1, transition: opacity 200ms ease-out` (без анимации ухода).

Записи лога, бары статуса и всё остальное появляются и меняются мгновенно,
без анимаций.

## 9. Окно и масштабирование

- Расчётный минимум — окно **1280x720** и больше; на нём всё содержимое видно
  без обрезки (с учётом полос прокрутки браузера).
- На `#screen-game` (как и на `body`) задаются `min-width: 1240px` и
  `min-height: 680px`. Если окно меньше, появляются обычные браузерные полосы
  прокрутки (`html, body { overflow: auto }`) — интерфейс не сжимается.
- **Media queries не используются.** Адаптивности нет.
- На окнах шире 1280px: панель остаётся 380px, карта расширяется, SVG (860px)
  остаётся по центру карты. Обработчик `resize` не нужен.
- Экраны `start`, `win`, `lose` центрируют свою колонку (max-width 560px)
  по горизонтали и вертикали.
