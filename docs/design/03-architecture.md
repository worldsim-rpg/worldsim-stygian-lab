# 03. Архитектура: нормативные требования к index.html

Статус: нормативный документ. Описывает структуру кода, схемы данных и
инженерные правила прототипа «Стигийская библиотека» — одного файла
`index.html` (vanilla JS + SVG + CSS, без сборки, без сети, без фреймворков).
Документ не содержит игрового контента (тексты комнат, событий, баланс) —
контент поставляется отдельным блоком итогового промпта, но обязан
соответствовать форматам данных, зафиксированным здесь. Везде, где приведён
код, он нормативен дословно (с точностью до пробелов). Все идентификаторы
в коде — английские, весь видимый игроку текст — русский, эмодзи запрещены
полностью (и в коде, и в UI, и в комментариях).

---

## 1. Структура index.html

Файл состоит из четырёх частей строго в этом порядке: `<head>` со `<style>`,
разметка `<body>`, один `<script>` в конце `<body>`, закрывающие теги.
Никаких внешних подключений: ни `<link>`, ни `<script src>`, ни `@import`,
ни `url(...)` с http/https — поиск по файлу строк `http://` и `https://`
должен давать 0 совпадений.

Скелет файла:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Стигийская библиотека — прототип</title>
<style>
/* ======================= STYLE ======================= */
/* весь CSS здесь, одним блоком, без url() и @import      */
</style>
</head>
<body>
<!-- ===================== РАЗМЕТКА ===================== -->
<!-- три экрана: start, game, end (схема ниже)            -->

<script>
'use strict';
// =====================================================
// 1. CONSTANTS / DATA
// =====================================================
// =====================================================
// 2. RNG
// =====================================================
// =====================================================
// 3. STATE
// =====================================================
// =====================================================
// 4. GENERATION
// =====================================================
// =====================================================
// 5. GRAPH / LAYOUT
// =====================================================
// =====================================================
// 6. RENDER
// =====================================================
// =====================================================
// 7. INPUT / ACTIONS
// =====================================================
// =====================================================
// 8. SAVE / LOAD
// =====================================================
// =====================================================
// 9. SCREENS
// =====================================================
// =====================================================
// 10. INIT
// =====================================================
</script>
</body>
</html>
```

Правила секционирования скрипта:

- Комментарии-разделители — ровно в показанном формате (линия из `=`,
  номер и имя секции, линия из `=`). Они обязаны присутствовать все десять,
  в этом порядке, и других разделителей такого вида в файле быть не должно.
- Каждая функция лежит строго в своей секции (реестр функций — раздел 10
  этого документа). Вызовы между секциями разрешены в любую сторону
  (function declarations поднимаются), но данные объявляются только
  в секции CONSTANTS / DATA.
- Внутри секции CONSTANTS / DATA — только `const`-объявления, никакой логики
  кроме литералов и `Object.freeze`.

### Разметка body (нормативные id)

Три экрана-контейнера, видимость переключается классом `hidden`
(`display: none`):

```html
<div id="screen-start" class="screen">

  <input id="seed-input" type="text">

  <button id="btn-start">Новая игра</button>

<div id="screen-game" class="screen hidden">
  <header id="topbar">
    <!-- название, кнопки: -->
    <button id="btn-new-game">Новая игра</button>
    <button id="btn-reset-save">Сбросить сейв</button>
  </header>
  <main id="game-layout">
    <div id="map-wrap">
      <svg id="map" xmlns="http://www.w3.org/2000/svg">
        <g id="edges"></g>
        <g id="nodes"></g>
      </svg>
    </div>
    <aside id="side">
      <section id="status"></section>      <!-- HP, Progress, Depth, Turn, цель -->
      <section id="room-panel"></section>  <!-- название и описание текущей комнаты -->
      <section id="actions"></section>     <!-- кнопки действий -->
      <section id="log"></section>         <!-- журнал событий -->
    </aside>
  </main>

<div id="screen-end" class="screen hidden">
  <!-- заголовок «Победа» / «Поражение», итоги, кнопка «Новая игра» -->
```

(`xmlns` в инлайновом SVG внутри HTML не обязателен, но указывается для
единообразия.) Раскладка `#game-layout`: flex-строка, `#map-wrap` занимает
всё свободное место, `#side` — фиксированные 360px справа. Тёмная тема,
только системные шрифты (`font-family: Georgia, "Times New Roman", serif`
для текста, `monospace` для цифр). Палитра по умолчанию: фон `#14161a`,
панели `#1d2026`, текст `#d8d4c8`, акцент `#c9a86a`, опасность `#b5524a`,
линии рёбер `#555c66`.

### Форматы данных в секции CONSTANTS / DATA

Все таблицы — массивы объектов, индекс в массиве = строка таблицы минус 1.
Нормативные формы (контент-блок промпта заполняет строки, не меняя полей):

```js
const CFG = Object.freeze({
  SAVE_KEY: 'stygian-proto-v1', // ключ localStorage
  SAVE_VERSION: 1,              // должен совпадать с meta.version сейва
  HP_START: 10,                 // стартовые и максимальные HP
  SVG_W: 1000,                  // ширина SVG, px
  BAND_H: 120,                  // высота полосы глубины, px
  SLOT_W: 110,                  // шаг сетки слотов по x, px
  SLOTS_PER_BAND: 9,            // слоты 0..8 в каждой полосе
  MAP_PAD_X: 60,                // отступ карты слева, px
  MAP_PAD_Y: 60,                // отступ карты сверху и снизу, px
  NODE_R: 18,                   // радиус узла-комнаты, px
  STUB_R: 14,                   // радиус узла-заглушки, px
  LOG_MAX: 60                   // максимум записей в журнале (DOM)
});

const LOCATIONS = [ /* ровно 30 строк, от обыденного к странному */ ];
// строка: { name: 'Читальный зал', tag: 'calm', desc: '1-2 предложения' }
// tag: 'calm' | 'lore' | 'danger' — машинная метка для механик действий

const DETAILS = [ /* ровно 30 строк, от обыденного к странному */ ];
// строка: { name: 'Тлеющий камин', desc: '1 предложение' }

const EVENTS = [ /* ровно 30 строк, от безобидного к опасному */ ];
// строка: { name: 'Тишина', text: 'описание', effect: {...} }
// effect: { type: 'none' }
//       | { type: 'hp',       value: -3 }        // value со знаком
//       | { type: 'progress', value: 2 }
//       | { type: 'item',     itemId: 'ink_balm' }
//       | { type: 'foe',      foeId: 'origami_golem' }

const FOES = [ /* существа, на которые ссылаются события */ ];
// строка: { id: 'origami_golem', name: 'Оригами-голем',
//           dmgMin: 1, dmgMax: 4, text: '1 предложение' }

const ITEMS = [ /* предметы инвентаря */ ];
// строка: { id: 'ink_balm', name: 'Чернильный бальзам',
//           kind: 'heal' | 'trophy', heal: 3, text: '1 предложение' }

const GOALS = [ // ровно 3 пресета сложности исследовательского вопроса
  { id: 'easy',     title: 'Общеизвестный вопрос', threshold: 15, minDepth: 3 },
  { id: 'standard', title: 'Редкое знание',        threshold: 25, minDepth: 6 },
  { id: 'hard',     title: 'Запретное знание',     threshold: 35, minDepth: 10 }
];
```

## 2. Схема объекта state

Ровно одна глобальная переменная верхнего уровня: `let state = null;`
(объявляется в секции STATE). Всё игровое состояние — внутри неё; сейв —
это `JSON.stringify(state)` без преобразований, поэтому в state запрещены
функции, `undefined`, `Map/Set`, циклические ссылки и DOM-узлы.

Полная схема (JSON с комментариями; значения — иллюстративный пример):

```jsonc
{
  "meta": {
    "version": 1              // number; равен CFG.SAVE_VERSION; при
                              // несовпадении при загрузке сейв игнорируется
  },

  "rng": {
    "seed": 1718012345,       // number (uint32); зерно партии, неизменно
    "counter": 137            // number; сколько случайных чисел уже взято;
                              // растёт на 1 при каждом вызове rand()
  },

  "player": {
    "hp": 7,                  // number; текущие очки здоровья, 0..maxHp;
                              // 0 = поражение
    "maxHp": 10,              // number; максимум HP (= CFG.HP_START)
    "progress": 12,           // number >= 0; счётчик Progress к цели
    "goal": {                 // выбранный на старте пресет цели
      "presetId": "standard", // string; "easy" | "standard" | "hard"
      "title": "Редкое знание",   // string; копия GOALS[i].title
      "threshold": 25,        // number; нужный Progress для победы
      "minDepth": 6           // number; минимальная глубина, на которой
                              // нужно побывать хотя бы раз
    },
    "inventory": [            // массив предметов; пустой = []
      { "itemId": "ink_balm", // string; id строки в таблице ITEMS
        "qty": 2 }            // number >= 1; количество (стопка)
    ],
    "position": 4,            // number; id узла, в котором стоит игрок;
                              // всегда узел kind === "room"
    "turn": 23,               // number; номер хода, растёт на 1 за действие
    "deepestDepth": 5         // number; максимальная глубина, на которой
                              // игрок побывал за партию (для победы)
  },

  "world": {
    "nodes": [ /* массив узлов графа, схема — раздел 3 */ ],
    "edges": [                // массив рёбер; ребро ненаправленное
      { "a": 0, "b": 1 }      // a, b: number — id узлов; инвариант a < b;
                              // дубликаты запрещены
    ],
    "nextId": 9               // number; id следующего создаваемого узла;
                              // только растёт, id никогда не переиспользуются
  }
}
```

Инварианты state (проверяются логикой, а не валидатором):

- `player.position` всегда указывает на существующий узел с `kind: "room"`.
- `player.hp` в диапазоне `0..maxHp`; `progress` не опускается ниже 0.
- Для каждого ребра `{a, b}`: `a` входит в `exits` узла `b` и наоборот
  (поле `exits` — денормализованный кэш рёбер, поддерживается `addEdge`).
- `rng.counter` сохраняется и загружается вместе со всем остальным —
  история бросков после загрузки продолжается с того же места.
- Журнал (лог) в state НЕ хранится: это эфемерный DOM; после загрузки
  сейва журнал начинается с записи «Игра загружена.».

## 3. Схема узла графа

Узел — одна комната (`kind: "room"`) или неисследованный выход-заглушка
(`kind: "stub"`, на карте — кружок со знаком вопроса). Заглушка при входе
в неё превращается в комнату на месте (тот же id, те же координаты).

```jsonc
{
  "id": 4,                // number; уникален в партии, выдаётся из world.nextId
  "depth": 2,             // number >= 0; глубина узла; 0 = вход; неизменна
  "kind": "room",         // "room" | "stub"
  "locationId": 7,        // number 1..30; строка таблицы LOCATIONS
                          // (результат d20+depth после clamp); у stub — null
  "detailId": 12,         // number 1..30; строка таблицы DETAILS; у stub — null
  "name": "Картохранилище (шестерни)", // string; готовая подпись:
                          // LOCATIONS[loc-1].name + " (" + DETAILS[det-1].name + ")";
                          // у stub — "?"
  "desc": "Стеллажи карт несуществующих берегов. Под полом вращаются шестерни.",
                          // string; LOCATIONS.desc + " " + DETAILS.desc;
                          // у stub — ""
  "tag": "lore",          // "calm" | "lore" | "danger" — копия LOCATIONS.tag;
                          // у stub — null
  "exits": [1, 7, 8],     // number[]; id соседних узлов (комнат и заглушек);
                          // зеркало world.edges, поддерживается addEdge
  "eventResolved": true,  // boolean; событие комнаты уже применено
                          // (применяется ровно один раз, при первом входе);
                          // у stub — false
  "visited": true,        // boolean; игрок был в узле хотя бы раз;
                          // у stub — false
  "x": 500,               // number; координата центра в SVG, px;
  "y": 300                // назначаются при создании узла (assignCoords)
                          // и НИКОГДА не пересчитываются
}
```

Правила:

- Снимки `name`, `desc`, `tag` хранятся в узле, чтобы рендер не лазил
  в таблицы; `locationId`/`detailId` хранятся для механик и отладки.
- Перегенерация запрещена: однажды материализованная комната постоянна;
  при повторном входе броски не выполняются (`eventResolved` защищает
  событие, `kind === "room"` защищает локацию и деталь).
- Заглушки создаются только функцией `planExits` материализованной комнаты;
  каждая заглушка с момента создания имеет id, depth, x, y и одно ребро
  к родителю.

## 4. Seeded RNG

Вся случайность в игре проходит через три функции: `rand`, `roll`,
`rollRange`. Вызов `Math.random` запрещён — поиск по файлу должен давать
0 совпадений. Секция RNG нормативно состоит из этого кода:

```js
function mulberry32(a) {
  return function () {
    var t = a += 0x6D2B79F5;
    t = Math.imul(t ^ t >>> 15, t | 1);
    t ^= t + Math.imul(t ^ t >>> 7, t | 61);
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}

// Единственный источник случайности. Значение детерминированно зависит
// только от пары (seed, counter): каждый вызов увеличивает counter и
// хеширует пару через mulberry32. Поскольку counter лежит в state и
// попадает в сейв, загрузка продолжает ту же последовательность бросков —
// никакого «переигрывания» и никаких теневых генераторов вне state.
function rand() {
  state.rng.counter += 1;
  var h = (state.rng.seed ^ Math.imul(state.rng.counter, 0x9E3779B9)) >>> 0;
  return mulberry32(h)();
}

// Бросок кубика: целое 1..sides включительно.
function roll(sides) {
  return 1 + Math.floor(rand() * sides);
}

// Целое в диапазоне a..b включительно (a <= b).
function rollRange(a, b) {
  return a + Math.floor(rand() * (b - a + 1));
}
```

Правила использования:

- Любой игровой бросок — только `roll` / `rollRange`; прямые вызовы
  `rand()` допустимы только для вероятностей вида `rand() < 0.15`,
  но предпочтительна форма `roll(20) <= 3`.
- Бросок генерации комнаты: `clampRow(roll(20) + depth)` (см. раздел про
  GENERATION в реестре функций; `clampRow(n)` возвращает
  `Math.max(1, Math.min(30, n))` — явный clamp результатов выше 30
  к строке 30; строки 30 таблиц обязаны быть пригодны к многократному
  выпадению).
- seed задаётся на старте партии: содержимое `#seed-input`; если строка
  состоит только из цифр — `parseInt(...) >>> 0`; если пустая —
  `Date.now() >>> 0`; иначе — свёртка символов в uint32 по схеме
  `h = (Math.imul(h, 31) + code) >>> 0`, начиная с `h = 2166136261`.
  seed отображается на экране игры (в `#status`), чтобы партию можно было
  воспроизвести.

## 5. Алгоритм раскладки карты

Карта растёт вниз: глубина — вертикальная ось. Координаты узла назначаются
один раз при создании и больше никогда не пересчитываются (никакого
force-layout, никаких пересборок раскладки).

Полосы (bands):

- Каждой глубине соответствует горизонтальная полоса:
  `y = CFG.MAP_PAD_Y + depth * CFG.BAND_H`, то есть `y = 60 + depth * 120`.
  Вход (depth 0) — в верхней полосе.

Слоты (slots):

- В каждой полосе ровно `CFG.SLOTS_PER_BAND = 9` слотов с индексами 0..8.
  Координата слота: `x = CFG.MAP_PAD_X + slot * CFG.SLOT_W`, то есть
  `x = 60 + slot * 110` (диапазон 60..940 при ширине SVG 1000).
- Один слот полосы занимает не более одного узла. Занятость полосы
  вычисляется сканом `world.nodes` нужной глубины; обратное преобразование:
  `slot = Math.round((node.x - CFG.MAP_PAD_X) / CFG.SLOT_W)`.
- Вход (узел id 0) ставится в центральный слот 4 полосы 0.

Назначение слота новому узлу (`assignCoords(node, parent)`):

1. Вычислить желаемый слот: `want = slot(parent)` — слот родителя.
2. Перебирать кандидатов в порядке `want, want+1, want-1, want+2, want-2,
   ..., want+8, want-8`, отбрасывая значения вне 0..8.
3. Первый свободный слот в полосе `node.depth` — берём; записываем
   `node.x`, `node.y` и больше не трогаем.
4. Если свободных слотов нет — узел не создаётся (см. правило ёмкости).

Правило ёмкости полосы: `planExits` ПЕРЕД созданием заглушек проверяет
число свободных слотов в целевой полосе и создаёт не больше заглушек, чем
там есть мест. Полоса вмещает максимум 9 узлов; переполнение невозможно
по построению. Вход всегда получает ровно 2 заглушки вглубь (полоса 1
заведомо пуста); обычная комната получает 1 заглушку вглубь, а при
`roll(6) >= 5` — 2 (если хватает слотов). Дополнительно, при `roll(20) <= 3`
новая комната соединяется боковым ребром с уже существующей комнатой своей
глубины, отстоящей не более чем на 2 слота (если такая есть и ребра ещё
нет), — это создаёт циклы в графе; новый узел при этом не создаётся.

Рёбра:

- Ребро между полосами (родитель глубже/выше ребёнка на 1) рисуется мягкой
  кубической кривой с вертикальными касательными:
  `M x1 y1 C x1 (y1+60), x2 (y2-60), x2 y2`
  (60 = `BAND_H / 2`; узел с меньшим y — первый).
- Боковое ребро внутри одной полосы — прямая линия `M x1 y1 L x2 y2`.
- Рёбра не несут интерактивности и рисуются под узлами (группа `#edges`
  стоит в SVG раньше `#nodes`).

## 6. Рендер

Принцип: один вход — `render()`. Каждый обработчик действия после мутации
state вызывает `render()` (через `endTurn()` либо напрямую). Никакого
точечного патчинга карты — только полная пересборка.

SVG-карта:

- `renderMap()` при каждом вызове полностью очищает группы `#edges` и
  `#nodes` (`replaceChildren()`) и строит их заново из `state.world`.
  До 300 узлов это заведомо дешевле любых диффов — порог прототипа.
- Размеры: при каждом рендере вычисляется
  `maxDepth = max(node.depth)` по всем узлам (включая заглушки) и
  `H = CFG.MAP_PAD_Y * 2 + maxDepth * CFG.BAND_H`. На `#map` выставляются
  атрибуты `width="1000"`, `height="${H}"`, `viewBox="0 0 1000 ${H}"` —
  масштаб строго 1:1, без зума.
- Прокрутка: `#map-wrap { overflow-y: auto; overflow-x: auto; }`, высота —
  вся доступная высота окна под шапкой. Колесо мыши прокручивает карту
  вертикально средствами браузера; никакого drag-pan и зума не реализуется.
  В конце `render()` контейнер прокручивается так, чтобы текущий узел был
  виден: `wrap.scrollTop = node.y - wrap.clientHeight / 2` (браузер сам
  ограничит диапазон).
- Узел-комната: `<g>` с `<circle r="18">` и `<text>` (имя — под кружком,
  сокращённое до 24 символов). Узел-заглушка: пунктирный `<circle r="14">`
  и `<text>?</text>` по центру. Текущая позиция игрока — обводка акцентным
  цветом и маркер. Соседи текущего узла (доступные для клика) — класс
  `clickable`, курсор pointer. Каждый `<g>` узла несёт атрибут
  `data-id="<node.id>"`.
- Клики: ровно ОДИН слушатель на группе `#nodes` (делегирование);
  по `closest('g[data-id]')` извлекается id и вызывается `onNodeClick(id)`.
  Слушатели на отдельные узлы не вешаются (их пересоздаёт каждый рендер).

Панели и журнал — обычный DOM, не SVG:

- `renderPanel()` перезаписывает `#status` (HP, Progress с порогом,
  текущая глубина, deepestDepth с minDepth, номер хода, seed), `#room-panel`
  (название и описание текущей комнаты) и `#actions` (кнопки доступных
  действий). Динамические строки вставляются только через `textContent`;
  `innerHTML` допустим только для статических шаблонов без данных.
- Журнал: `log(text)` добавляет `<p>` в начало `#log` и удаляет лишние
  сверх `CFG.LOG_MAX = 60`. Журнал append-only, в `render()` не участвует
  и в state не хранится.

## 7. Сейв / лоад

- Хранилище: `localStorage`, единственный ключ `CFG.SAVE_KEY =
  'stygian-proto-v1'`. Версия зашита и в ключ, и в `state.meta.version`.
- `saveGame()`: `localStorage.setItem(CFG.SAVE_KEY, JSON.stringify(state))`
  в `try/catch` (переполнение/приватный режим — молча пропустить, записать
  предупреждение в журнал).
- Автосейв: ровно одна точка вызова — внутри `endTurn()`, который
  выполняется в конце КАЖДОГО действия игрока (перемещение, осмотр,
  использование предмета). Плюс один вызов в `startNewGame()` сразу после
  создания state.
- `loadGame()`: читает ключ, `JSON.parse` в `try/catch`; возвращает `false`,
  если ключа нет, JSON битый или `parsed.meta.version !== CFG.SAVE_VERSION`.
  При несовпадении версии сейв игнорируется (не удаляется). При успехе
  присваивает `state = parsed` и возвращает `true`.
- Запуск (`init()`): если `loadGame()` вернул `true` — сразу экран игры
  и `render()`; иначе — стартовый экран.
- Кнопки: «Новая игра» (на стартовом экране — `#btn-start`, на экране игры —
  `#btn-new-game`, на финальном — `#btn-end-restart`) показывает стартовый
  экран и начинает новую партию по нажатию; «Сбросить сейв»
  (`#btn-reset-save`) выполняет `localStorage.removeItem(CFG.SAVE_KEY)` и
  показывает стартовый экран. Подтверждений-диалогов нет — это прототип.

## 8. Debug-хуки

В `init()` на `window` вешается объект `DBG` — единственный, помимо `state`,
преднамеренный глобальный идентификатор. Каждый хук — одна строка:

```js
window.DBG = {
  addProgress: function (n) { state.player.progress += n; render(); },
  teleport:    function (nodeId) { var n = getNode(nodeId); if (n && n.kind === 'room') { state.player.position = nodeId; render(); } },
  reveal:      function () { state.world.nodes.forEach(function (n) { n.visited = true; }); render(); },
  god:         function () { state.player.maxHp = 999; state.player.hp = 999; render(); }
};
```

Хуки не пишут автосейв (мутации попадут в сейв при следующем действии
игрока) и не двигают `rng.counter`.

## 9. Бюджет строк и правила качества

Ориентир объёма файла: 1500–2500 строк, целевое значение около 1900.
Распределение по секциям (диапазоны нормативны: выход за верхнюю границу
секции — сигнал упростить именно её, а не раздуть соседнюю):

| Часть файла              | Строки    |
|--------------------------|-----------|
| `<head>` + `<style>`     | 200–260   |
| Разметка `<body>`        | 60–100    |
| 1. CONSTANTS / DATA      | 380–520   |
| 2. RNG                   | 20–30     |
| 3. STATE                 | 40–70     |
| 4. GENERATION            | 160–240   |
| 5. GRAPH / LAYOUT        | 80–130    |
| 6. RENDER                | 240–340   |
| 7. INPUT / ACTIONS       | 200–300   |
| 8. SAVE / LOAD           | 50–80     |
| 9. SCREENS               | 80–140    |
| 10. INIT (+ DBG)         | 30–60     |
| Итого                    | 1540–2270 |

Правила качества (нормативные):

1. `'use strict';` первой строкой скрипта. Одна глобальная переменная —
   `let state`. Кроме неё на верхнем уровне — только `const`-данные секции 1
   и function declarations. `window.DBG` — единственное намеренное
   присваивание в `window`.
2. Данные строго отдельно от логики: весь игровой контент (названия,
   описания, баланс, таблицы) — только в секции CONSTANTS / DATA. Функции
   генерации читают таблицы по индексам и не содержат контентных строк.
   Русские строки UI (подписи кнопок, шаблоны записей журнала) допустимы
   в RENDER / ACTIONS / SCREENS.
3. Чистота по секциям: GENERATION и GRAPH / LAYOUT не трогают DOM; RENDER
   читает state, но не мутирует его; мутируют state только GENERATION,
   INPUT / ACTIONS, SAVE / LOAD (загрузка) и STATE (фабрика).
4. Случайность — только через `rand` / `roll` / `rollRange` (раздел 4);
   `Math.random` в файле отсутствует.
5. Идентификаторы, ключи данных, классы CSS, id элементов — английские;
   русский — только в строковых значениях и комментариях.
6. Динамический текст вставляется только через `textContent` /
   `createElement`; `innerHTML` — только для статических шаблонов без
   подстановок.
7. Никаких `setTimeout`, промисов, `async` — ход полностью синхронный.
   Никаких внешних ресурсов и сетевых запросов.
8. Функция не длиннее 60 строк, вложенность блоков не глубже 3; ранние
   `return` вместо лестниц `else`.
9. Эмодзи запрещены везде; иконки — SVG-примитивы или буквы.

## 10. Реестр функций (скелет реализации)

40 функций. Имена и сигнатуры нормативны; реализация обязана разложить их
по указанным секциям. `Node` ниже — объект узла из раздела 3.

### 2. RNG

| Сигнатура | Назначение |
|---|---|
| `mulberry32(a: number): () => number` | Фабрика PRNG по 32-битному зерну (код в разделе 4). |
| `rand(): number` | Единственный источник случайности [0,1); инкрементирует `state.rng.counter`. |
| `roll(sides: number): number` | Бросок кубика: целое 1..sides. |
| `rollRange(a: number, b: number): number` | Целое a..b включительно. |

### 3. STATE

| Сигнатура | Назначение |
|---|---|
| `newState(seed: number, presetId: string): object` | Фабрика начального state: игрок, цель из GOALS, вход (узел 0, слот 4) и его 2 заглушки. |
| `getNode(id: number): Node \| undefined` | Поиск узла по id в `state.world.nodes`. |

### 4. GENERATION

| Сигнатура | Назначение |
|---|---|
| `clampRow(n: number): number` | Приведение результата d20+depth к строке таблицы: `max(1, min(30, n))`. |
| `rollLocation(depth: number): { row: number, def: object }` | Бросок `clampRow(roll(20)+depth)` по LOCATIONS. |
| `rollDetail(depth: number): { row: number, def: object }` | Тот же бросок по DETAILS. |
| `rollEvent(depth: number): { row: number, def: object }` | Тот же бросок по EVENTS. |
| `addNode(fields: object): Node` | Создаёт узел с `id = world.nextId++`, кладёт в `world.nodes`. |
| `addEdge(aId: number, bId: number): void` | Добавляет ребро `{a: min, b: max}` без дублей и зеркалит в `exits` обоих узлов. |
| `createStub(parent: Node): Node \| null` | Заглушка на `parent.depth + 1`: слот через `assignCoords`, ребро к родителю; `null`, если полоса полна. |
| `materializeStub(stub: Node): Node` | Превращает заглушку в комнату на месте: броски локации/детали/события, заполнение полей, затем `planExits`. |
| `planExits(node: Node): void` | Создаёт 1–2 заглушки вглубь (вход — ровно 2) и с шансом `roll(20) <= 3` боковое ребро к комнате той же глубины (правила — раздел 5). |

### 5. GRAPH / LAYOUT

| Сигнатура | Назначение |
|---|---|
| `bandY(depth: number): number` | `MAP_PAD_Y + depth * BAND_H`. |
| `slotX(slot: number): number` | `MAP_PAD_X + slot * SLOT_W`. |
| `nearestFreeSlot(depth: number, want: number): number \| null` | Ближайший свободный слот полосы к want (порядок перебора — раздел 5). |
| `assignCoords(node: Node, parent: Node \| null): void` | Назначает узлу x/y один раз; для входа — слот 4 полосы 0. |

### 6. RENDER

| Сигнатура | Назначение |
|---|---|
| `render(): void` | Единая точка перерисовки: размеры SVG, `renderMap`, `renderPanel`, прокрутка к текущему узлу. |
| `renderMap(): void` | Полная пересборка групп `#edges` и `#nodes` из `state.world`. |
| `nodeSvg(node: Node): SVGGElement` | Строит `<g data-id>` одного узла (комната или заглушка, подсветка текущего/кликабельных). |
| `edgeSvg(edge: object): SVGPathElement` | Строит `<path>` ребра (кривая между полосами, прямая внутри полосы). |
| `renderPanel(): void` | Перезаписывает `#status`, `#room-panel`, `#actions` из state. |
| `log(text: string): void` | Добавляет запись в `#log` (DOM, максимум 60, новые сверху). |

### 7. INPUT / ACTIONS

| Сигнатура | Назначение |
|---|---|
| `onNodeClick(id: number): void` | Делегированный клик по карте: игнор, если игра окончена или узел не сосед текущего; иначе `moveTo`. |
| `moveTo(id: number): void` | Перемещение: для заглушки — `materializeStub`; вход в комнату, `visited = true`, `resolveEvent`, `endTurn`. |
| `searchRoom(): void` | Действие «Осмотреться» в текущей комнате: бросок с учётом `tag`, прирост Progress или находка/стычка, `endTurn`. |
| `resolveEvent(node: Node): void` | Применяет событие комнаты ровно один раз (`eventResolved`), пишет в журнал. |
| `applyEffect(effect: object): void` | Интерпретатор effect-объектов данных: none / hp / progress / item / foe. |
| `fightFoe(foeId: string): void` | Ультра-лёгкая стычка: синхронный обмен — урон игроку `rollRange(dmgMin, dmgMax)`, исход в журнал; без отдельных экранов. |
| `useItem(itemId: string): void` | Использование предмета kind 'heal' из инвентаря; тратит ход (`endTurn`). |
| `changeHp(delta: number): void` | Изменяет hp с clamp 0..maxHp. |
| `checkEnd(): 'win' \| 'lose' \| null` | lose: `hp <= 0`; win: `progress >= threshold` и `deepestDepth >= minDepth` и `position === 0`. |
| `endTurn(): void` | Финал каждого действия: `turn++`, обновить `deepestDepth`, `saveGame`, `render`, при исходе — `showEnd`. |

### 8. SAVE / LOAD

| Сигнатура | Назначение |
|---|---|
| `saveGame(): void` | `setItem(CFG.SAVE_KEY, JSON.stringify(state))` в try/catch. |
| `loadGame(): boolean` | Читает и парсит сейв; `false` при отсутствии, битом JSON или несовпадении `meta.version`. |
| `resetSave(): void` | `removeItem(CFG.SAVE_KEY)` и возврат на стартовый экран. |

### 9. SCREENS

| Сигнатура | Назначение |
|---|---|
| `showScreen(name: 'start' \| 'game' \| 'end'): void` | Переключает классы `hidden` трёх экранов. |
| `startNewGame(seedText: string, presetId: string): void` | Парсит seed (правила — раздел 4), `state = newState(...)`, `saveGame`, экран игры, `render`. |
| `showEnd(result: 'win' \| 'lose'): void` | Заполняет финальный экран (итоги: ходы, глубина, Progress) и показывает его. |

### 10. INIT

| Сигнатура | Назначение |
|---|---|
| `init(): void` | Точка входа (вызов — последняя строка скрипта): навешивает обработчики UI (кнопки, делегирование `#nodes`), ставит `window.DBG`, затем `loadGame() ? (showScreen('game'), render()) : showScreen('start')`. |
