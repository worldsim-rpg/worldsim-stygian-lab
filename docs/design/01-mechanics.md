# 01. Правила игры (механика)

Нормативная спецификация игровой механики прототипа «Стигийская библиотека» —
соло depth crawl по мотивам The Stygian Library (Emmy Allen). Один файл
`index.html`, vanilla JS + SVG + CSS, пошаговая игра, интерфейс на русском,
идентификаторы в коде английские, эмодзи запрещены везде.

Все числа в этом документе обязательны к реализации точно как написано.
Слова «бросок dN» означают равновероятное целое от 1 до N из единственного
seeded-потока mulberry32. Порядок потребления бросков фиксирован псевдокодом
раздела 10; никакие визуальные эффекты не потребляют броски из этого потока.

Содержимое 30-строчных таблиц локаций и деталей (тексты строк), описания
существ и шаблоны записей журнала задаются в документе контента и не входят
в этот документ; здесь нормированы только их структура, номера особых строк,
статы существ и все формулы.

## 0. Сводка констант

| Константа (id в коде) | Значение | Смысл |
|---|---|---|
| `HP_MAX` | 20 | максимум и стартовое значение hp |
| `START_PROGRESS` | 3 | стартовый progress |
| `INVENTORY_MAX` | 6 | слотов инвентаря |
| `TALK_DC` | 12 | сложность проверки «Говорить» (d20 + мод реакции) |
| `FLEE_DC` | 10 | сложность проверки «Бежать» (d20, без модификаторов) |
| `WANDER_PERIOD` | 3 | период плановой проверки бродячей встречи (ходы) |
| `WANDER_LIMIT` | 5 | счётчик блуждания, при котором списывается 1 progress |
| `DEEP_BONUS_DEPTH` | 6 | глубина, с которой действует «бонус глубины» |
| `REST_HEAL` | 2 | восстановление hp действием «Отдохнуть» |
| `MAX_NODES_PER_DEPTH` | 10 | максимум узлов (комнат и заглушек) на одной глубине |
| `TABLE_ROWS` | 30 | строк в таблицах локаций и деталей |
| `SPECIAL_ROWS` | 4, 8, 12, 16, 20, 24, 27, 30 | особые строки таблицы локаций |

## 1. Персонаж и старт

### 1.1. Характеристики персонажа

Персонаж один, без классов и листа характеристик. Состояние персонажа:

- `hp` — очки здоровья. Старт: 20. Максимум: 20. Никогда не поднимается
  выше 20. При `hp <= 0` — немедленное поражение (раздел 6.4).
- `progress` — счётчик приближения к ответу на исследовательский вопрос.
  Старт: 3 (эрудиция самого персонажа). Минимум 0, верхней границы нет.
- `inventory` — список предметов, максимум 6 слотов, 1 предмет = 1 слот.
  Старт: пусто.
- Производные счётчики партии: `turn` (номер хода, старт 0), `depth`
  (глубина текущей комнаты, старт 0), `maxDepth` (наибольшая посещённая
  глубина, старт 0), `wanderCount` (счётчик блуждания, старт 0).

### 1.2. Исследовательский вопрос: три пресета

На стартовом экране игрок выбирает ровно один пресет (по умолчанию первый):

| id | Имя | Пример вопроса | Порог progress | Мин. глубина |
|---|---|---|---|---|
| `easy` | «Забытый рецепт» | «Каков был рецепт чернил, которыми написан Велленхольмский кодекс?» | 10 | 3 |
| `medium` | «Утраченная биография» | «Кем на самом деле была картограф Ирен Вольц и куда она исчезла?» | 20 | 6 |
| `hard` | «Запретный гримуар» | «Что написано на последней странице Гримуара Бессонных и почему её нельзя читать вслух?» | 30 | 10 |

Порог и минимальная глубина фиксируются на всю партию. Сменить пресет можно
только новой партией.

### 1.3. Старт партии

При нажатии «Войти в библиотеку»:

1. Инициализируется RNG из seed (поле seed; пустое — случайное целое
   1..999999, оно становится seed партии и показывается в статусе).
2. Создаётся узел входа: `entrance`, depth 0, название «Вход», локация вне
   таблиц (тег `entrance`), без события, без особости, осмотр доступен по
   общим правилам обычной локации.
3. К входу добавляются ровно 2 заглушки глубины 1 (без бросков направления).
4. Игрок помещается во вход. `turn = 0`, `hp = 20`, `progress = 3`.

### 1.4. Что игрок видит и знает на старте

Видит: карту с узлом входа (depth 0, верхняя полоса) и двумя заглушками со
знаком вопроса на глубине 1; панель статуса (hp 20/20, глубина 0 с пометкой
требуемой, progress 3/порог, ход 0, seed); блок текущей комнаты с описанием
входа; кнопки действий («Осмотреться», «Сдаться»); журнал с записью о начале
партии.

Знает (текстом в описании пресета и стартовой записью журнала): порог
progress, минимальную глубину, и правило победы — «наберите порог, побывайте
на нужной глубине, вернитесь ко входу живым». Игрок НЕ видит: содержимое
заглушек до их открытия, таблицы, броски будущих комнат. Все совершённые
броски и их результаты честно пишутся в журнал.

## 2. Структура хода

### 2.1. Конечный автомат

Верхний уровень — четыре экрана: `start`, `game`, `win`, `lose`. Внутри
`game` состояние определяется парой «существо в текущей комнате; его
реакция». Существо в комнате может быть не более одного. Возможные
состояния: `idle` (существа нет), `friendly`, `neutral`, `wary`, `hostile`
(реакции существа, раздел 5.1).

Матрица доступности действий (да/нет):

| Действие | idle | friendly | neutral | wary | hostile |
|---|---|---|---|---|---|
| Перейти в открытую соседнюю комнату (клик по узлу) | да | да | да | да | нет |
| Перейти в соседнюю заглушку (клик по узлу) | да | да | да | нет | нет |
| Осмотреться (если комната ещё не осмотрена) | да | да | да | нет | нет |
| Отдохнуть (если hp < 20) | да | нет | нет | нет | нет |
| Говорить (если существо не бессловесное) | нет | да | да | да | нет |
| Сражаться | нет | да | да | да | да |
| Бежать | нет | нет | нет | нет | да |
| Использовать предмет (клик по предмету в инвентаре) | да | да | да | да | да |
| Сдаться (кнопка, с подтверждением) | да | да | да | да | да |

Перемещение выполняется кликом по соседнему узлу карты; остальные действия —
кнопками панели. Недоступные действия не показываются. Кнопок действий
одновременно не больше четырёх, «Сдаться» всегда последняя.

### 2.2. Стоимость действий

| Действие | Стоимость |
|---|---|
| Перейти (в открытую или в заглушку) | 1 ход |
| Осмотреться | 1 ход |
| Отдохнуть | 1 ход |
| Говорить | 1 ход |
| Сражаться (один раунд) | 1 ход |
| Бежать (одна попытка) | 1 ход |
| Использовать предмет | 0 ходов (свободное действие) |
| Подбор предмета | 0 ходов (автоматический, см. 9.6) |
| Сдаться | завершает партию |

### 2.3. Порядок разрешения хода

Каждое действие стоимостью 1 ход разрешается строго так:

1. Действие исполняется полностью (включая ответ врага в раунде боя или
   свободную атаку при провале бегства).
2. `turn += 1`. Счётчик хода виден в статусе всегда.
3. Проверка смерти: если `hp <= 0` — экран `lose`, дальнейшие шаги не
   выполняются.
4. Проверка победы: если игрок находится в узле входа и условия победы
   выполнены (раздел 6.3) — экран `win`, дальнейшие шаги не выполняются.
5. Проверка бродячей встречи (раздел 7), если положено по таймингу.
6. Автосейв в localStorage.

Свободные действия (предметы) не двигают `turn`, не вызывают проверок
бродячих встреч, но тоже завершаются проверкой смерти/победы и автосейвом.

### 2.4. Действие «Осмотреться»

Доступно один раз на комнату (`room.searched = false`), запрещено при
существе в состоянии wary или hostile. Разрешение:

- Особая локация (строка локации входит в `SPECIAL_ROWS`):
  `progress += 3` (на глубине >= 6: `+= 4`); затем бросок d20: при 15-20
  в комнате появляется предмет (бросок по таблице находок, раздел 4.3).
- Обычная локация: бросок d20: 1-8 — ничего; 9-14 — `progress += 1`;
  15-20 — предмет (таблица находок).

После разрешения комната помечается осмотренной навсегда. Осмотр всегда
вызывает дополнительную проверку бродячей встречи (раздел 7).

### 2.5. Действие «Отдохнуть»

Доступно при отсутствии существа в комнате и `hp < 20`. Эффект: `hp += 2`
(не выше 20). Отдых всегда вызывает дополнительную проверку бродячей
встречи (раздел 7); на глубине 0 бродячих встреч не бывает, поэтому отдых
у входа безопасен, но тратит ходы и разгоняет счётчик блуждания при
последующих спусках.

## 3. Генерация комнаты при переходе в заглушку

### 3.1. Заглушки

Заглушка — узел графа с известной глубиной, но без содержимого. Клик по
заглушке, соседней с текущей комнатой, выполняет процедуру `generateRoom`
и перемещает игрока в созданную комнату (это один ход).

### 3.2. Процедура (нормативный порядок бросков)

Для заглушки глубины `d`:

1. Бросок локации: `locRow = d20 + d`; если результат больше 30 —
   считается ровно 30 (clamp). Результат меньше 1 невозможен.
   Получившаяся строка таблицы локаций определяет название, описание,
   тег и особость комнаты (`special = SPECIAL_ROWS.includes(locRow)`).
2. Бросок детали: `detRow = d20 + d`, тот же clamp до 30. Строка таблицы
   деталей добавляет описание-деталь.
3. Выходы. Бросок d6:
   - 1 — комната получает 0 новых заглушек (тупик, вероятность 1/6);
   - 2-4 — 1 новую заглушку (вероятность 1/2);
   - 5-6 — 2 новые заглушки (вероятность 1/3).
   Для каждой новой заглушки отдельно бросок d10 на направление:
   - 1-7 (70 процентов) — вглубь: заглушка глубины `d + 1`;
   - 8-10 (30 процентов) — вбок: заглушка той же глубины `d`.
   Ограничение полосы: если на выбранной глубине уже 10 узлов (комнат и
   заглушек суммарно), направление заменяется на альтернативное; если обе
   полосы заполнены — заглушка не создаётся.
4. Событие: бросок d12 по таблице событий (раздел 4). Если заглушка была
   «многообещающей» (раздел 5.4), к броску прибавляется 3, итог выше 12
   считается 12.
5. Гарантия фронтира: если после шагов 3-4 во всём графе не осталось ни
   одной заглушки, текущая комната принудительно получает одну заглушку
   глубины `d + 1` (если полоса `d + 1` заполнена — `d + 2`, и так далее).

Комната записывается в граф навсегда: повторное посещение никогда не
перегенерирует ни локацию, ни деталь, ни событие. Дубликаты строк локаций
в разных комнатах допустимы и нормальны.

### 3.3. Правило clamp и стратификация

Таблицы локаций и деталей содержат ровно по 30 строк, отсортированных от
обыденного (строка 1) к самому странному (строка 30). На глубине `d`
доступно окно строк `1 + d .. 20 + d` с clamp до 30: начиная с глубины 10
окно упирается в строку 30, начиная с глубины 29 любой бросок даёт
строку 30. Это допустимо: глубина 29+ — заведомо за пределами целевых
партий.

### 3.4. Гарантия отсутствия софтлока

Граф — дерево с корнем в узле входа: каждая новая заглушка соединяется
ребром ровно с одной родительской комнатой, рёбра никогда не удаляются,
узлы не сливаются. Следствия, обязательные к соблюдению:

- из любой комнаты существует путь по открытым комнатам до входа;
- перемещение по открытым комнатам не запрещается ничем, кроме состояния
  hostile, из которого всегда доступно повторяемое действие «Бежать»;
- тупик (0 новых выходов) не опасен: ребро, по которому игрок пришёл,
  всегда существует;
- библиотека не может «закончиться»: правило гарантии фронтира (3.2 шаг 5)
  поддерживает хотя бы одну заглушку в графе всегда.

## 4. События

### 4.1. Таблица событий (d12)

Бросается один раз при генерации комнаты. При повторных посещениях событие
не перебрасывается и не повторяется.

| d12 | Событие | Эффект |
|---|---|---|
| 1 | Тишина | Ничего не происходит. |
| 2 | Тишина | Ничего не происходит. |
| 3 | Тишина | Ничего не происходит. |
| 4 | Дезинформация | Ложный каталог, подложная сноска: `progress -= 2` (не ниже 0). |
| 5 | Встреча | Появляется существо (раздел 5), бросок реакции 2d6 без модификаторов. |
| 6 | Встреча | То же, что строка 5. |
| 7 | Встреча | То же, что строка 5. |
| 8 | Опасная встреча | Существо (раздел 5), бросок реакции 2d6 с модификатором -3. |
| 9 | Феномен | Бросок d6 по суб-таблице феноменов (4.2). |
| 10 | Находка | В комнате предмет: бросок d6 по таблице находок (4.3). |
| 11 | Находка | То же, что строка 10. |
| 12 | Книга по теме | Том, прямо касающийся вопроса: `progress += 4` (на глубине >= 6: `+= 5`). |

### 4.2. Суб-таблица феноменов (d6)

| d6 | Феномен | Эффект |
|---|---|---|
| 1-2 | Шёпот стеллажей | Полки шепчут полезное: `progress += 1`. |
| 3-4 | Сдвиг пространства | Комната получает 1 дополнительную заглушку: направление по обычному правилу (d10: 1-7 вглубь, 8-10 вбок; с ограничением полосы из 3.2). |
| 5-6 | Пыльная мгла | Удушливое облако: `hp -= 2`, немедленная проверка смерти. |

### 4.3. Таблица находок (d6)

Используется событиями 10-11, осмотром (2.4) и добычей (5.6). Предмет
появляется в комнате и подбирается автоматически (9.6).

| d6 | Предмет (id) | Тип | Эффект |
|---|---|---|---|
| 1-2 | Бинты (`bandage`) | используемый | `hp += 4` (не выше 20). Расходуется. |
| 3 | Латунный нож для бумаг (`paper_knife`) | пассивный | +2 к урону игрока, пока в инвентаре. Эффект не суммируется от двух ножей. |
| 4 | Каталожная карточка (`catalog_card`) | используемый | `progress += 2`. Расходуется. |
| 5 | Фонарь с маслом (`lantern`) | используемый | Следующая попытка «Бежать» автоматически успешна. Расходуется при активации. |
| 6 | Закладка-оберег (`ward_bookmark`) | используемый | Следующий урон от существа по игроку становится 0. Расходуется при активации. |

Использование — свободное действие в любой момент своего хода, в том числе
в бою. Одновременно может быть активен только один фонарь и одна закладка
(повторная активация до срабатывания невозможна).

## 5. Встречи

### 5.1. Появление существа и бросок реакции

Источники существ: события 5-8 и бродячие встречи (раздел 7). Существо
появляется в текущей комнате; если в комнате уже есть существо, новое не
появляется (для событий 5-8 при генерации это невозможно; правило
актуально для бродячих встреч). Существо привязано к комнате и сохраняется
в ней, пока не убито: уйдя и вернувшись, игрок застанет его с той же
реакцией.

Строка существа: `clamp(d6 + floor(depth / 2), 1, 12)` по таблице существ:

| Строка | Существо (id) | hp | Урон | Знающее | Бессловесное |
|---|---|---|---|---|---|
| 1 | Заблудившийся читатель (`lost_reader`) | 3 | 1 | нет | нет |
| 2 | Рой книжной моли (`moth_swarm`) | 2 | 1 | нет | да |
| 3 | Служитель-новичок (`novice_clerk`) | 4 | 1 | да | нет |
| 4 | Оригами-голем (`origami_golem`) | 5 | 2 | нет | нет |
| 5 | Пылевой элементаль (`dust_elemental`) | 6 | 2 | нет | да |
| 6 | Библиотекарь серого ордена (`grey_librarian`) | 5 | 2 | да | нет |
| 7 | Ожившая книга-хищник (`predator_book`) | 7 | 3 | нет | нет |
| 8 | Чернильный призрак (`ink_ghost`) | 6 | 3 | нет | нет |
| 9 | Библиотекарь чёрного ордена (`black_librarian`) | 8 | 3 | да | нет |
| 10 | Скелет-архивариус (`skeleton_archivist`) | 9 | 3 | да | нет |
| 11 | Страж запретного отдела (`vault_warden`) | 12 | 4 | нет | да |
| 12 | То-Что-Читает (`that_which_reads`) | 14 | 5 | да | нет |

Бросок реакции: 2d6 плюс модификатор источника (событие 8: -3; иначе 0):

| Итог | Реакция |
|---|---|
| 3 и меньше | hostile (враждебно) |
| 4-6 | wary (настороженно) |
| 7-9 | neutral (нейтрально) |
| 10 и больше | friendly (дружелюбно) |

### 5.2. Поведение по реакциям

- **hostile**: блокирует перемещение и осмотр; игроку доступны только
  «Сражаться», «Бежать», предметы, «Сдаться». Существо наносит урон только
  в ответ: на раунд боя (5.5) и на провал бегства (5.7). Само по себе
  стояние в комнате урона не наносит (но потратить ход, не сражаясь и не
  убегая, невозможно — других действий нет).
- **wary**: не атакует; запрещает осмотр и переходы в заглушки; уйти в
  открытые комнаты можно свободно. Доступно «Говорить» и «Сражаться».
- **neutral**: занимается своими делами; ничего не запрещает, кроме
  отдыха. Доступно «Говорить» и «Сражаться».
- **friendly**: расположено к игроку; как neutral, но проверка разговора
  с бонусом +4.

### 5.3. Действие «Говорить»

Доступно, если существо не hostile и не бессловесное. Проверка:
`d20 + мод >= 12`, где мод: friendly +4, neutral 0, wary -4.

- **Успех**: реакция улучшается на одну ступень (wary -> neutral ->
  friendly; выше friendly не растёт). Если награда с этого существа ещё
  не получена (`rewardGiven = false`):
  - знающее существо: `progress += 3`;
  - не знающее: подсказка (5.4); если заглушек в графе нет — `progress += 1`;
  - после выдачи `rewardGiven = true` (повторные успехи дают только
    улучшение реакции).
- **Провал**: реакция ухудшается на одну ступень (friendly -> neutral ->
  wary -> hostile). Ставшее hostile существо урон в момент провала не
  наносит — бой начинается со следующего действия игрока.

### 5.4. Подсказка

Случайная заглушка графа (равновероятно; приоритет — заглушки, соседние с
текущей комнатой, если такие есть) помечается «многообещающей»
(`stub.hinted = true`). При её открытии бросок события получает +3
(итог выше 12 считается 12) — смещение к находкам и книге. Одна заглушка
не может быть помечена дважды; в журнал пишется, какое направление указали.

### 5.5. Действие «Сражаться» (раунд боя)

Один раунд = один ход. Формулы однозначны, промахов нет:

1. Игрок наносит урон: `d6` (+2, если в инвентаре латунный нож). Урон
   вычитается из hp существа.
2. Если существо погибло (`hp <= 0`) — добыча (5.6), раунд окончен.
3. Если существо было не hostile — оно становится hostile и в этом раунде
   не отвечает.
4. Если существо hostile — оно отвечает: игрок получает урон, равный
   фиксированному значению «Урон» из строки существа (активная
   закладка-оберег обнуляет этот урон и расходуется). Проверка смерти.

Атака по friendly/neutral/wary существу разрешена и немедленно делает его
hostile (шаг 3): убийство — всегда вариант, но знания убитого теряются.

### 5.6. Смерть существа и добыча

Существо удаляется из комнаты навсегда. Бросок d6:

- 1-3 — ничего;
- 4-5 — предмет (бросок по таблице находок 4.3);
- 6 — предмет (таблица находок) и `progress += 1` (записки, обрывки).

Никаких иных штрафов и наград за убийство нет, в том числе за убийство
библиотекарей.

### 5.7. Действие «Бежать»

Доступно только при hostile. Цель бегства всегда одна и выбора не требует:
комната, из которой игрок пришёл в текущую (`lastRoom`; хранится в
состоянии и обновляется при каждом переходе). Разрешение:

- если активирован фонарь — автоуспех, фонарь расходуется;
- иначе проверка `d20 >= 10`.
- **Успех**: игрок перемещается в `lastRoom` (существо остаётся в своей
  комнате, hostile).
- **Провал**: свободная атака существа — игрок получает его фиксированный
  урон (закладка-оберег применима), остаётся на месте, проверка смерти.
  Попытку можно повторять каждый ход без ограничений.

## 6. Progress

### 6.1. Источники (полный список)

| Источник | Очки |
|---|---|
| Книга по теме (событие 12) | +4; на глубине >= 6: +5 |
| Первый успешный разговор со знающим существом | +3 |
| Осмотр особой локации (строки 4, 8, 12, 16, 20, 24, 27, 30) | +3; на глубине >= 6: +4 |
| Осмотр обычной локации, d20 = 9-14 | +1 |
| Феномен «Шёпот стеллажей» | +1 |
| Каталожная карточка (предмет) | +2 |
| Добыча с существа, d6 = 6 | +1 |
| Первый успешный разговор с не знающим существом при отсутствии заглушек | +1 (вместо подсказки) |

### 6.2. Штрафы

| Штраф | Очки | Условие |
|---|---|---|
| Дезинформация (событие 4) | -2 | при генерации комнаты |
| Блуждание | -1 | `wanderCount` достиг 5 (см. ниже), затем счётчик обнуляется |

Правило блуждания. `wanderCount += 1` при каждом переходе в уже посещённую
комнату, глубина которой больше или равна глубине покидаемой комнаты
(движение строго вверх, к выходу, никогда не штрафуется). Счётчик
сбрасывается в 0 при открытии новой комнаты и при любом начислении
положительного progress. Progress не опускается ниже 0.

### 6.3. Победа

Победа наступает, когда одновременно:

1. `progress >= порог пресета`, И
2. `maxDepth >= минимальная глубина пресета`, И
3. игрок находится в узле входа (depth 0), И
4. `hp > 0`.

Проверка выполняется при каждом входе в узел входа и после каждого
изменения progress, пока игрок стоит во входе. При выполнении — экран
`win` немедленно, без дополнительной кнопки. Если progress упал ниже
порога до возвращения (дезинформация, блуждание) — победы нет, порог
нужно добрать заново: условие проверяется только в текущий момент,
прошлые значения не засчитываются.

### 6.4. Поражение

`hp <= 0` в любой момент — немедленный экран `lose`. Смерть проверяется
сразу после любого получения урона и имеет приоритет над всеми прочими
эффектами (раздел 9.4).

### 6.5. Выход ни с чем

Кнопка «Сдаться» доступна всегда (с инлайн-подтверждением): партия
завершается, автосейв стирается, открывается экран `start`. Это не
поражение (экран `lose` не показывается) и не победа. Стоя у входа без
выполненных условий, игрок выходит из библиотеки именно так.

## 7. Бродячие встречи

### 7.1. Когда проверяются

Проверка бродячей встречи выполняется на шаге 5 порядка разрешения хода
(2.3), если выполнено хотя бы одно:

- номер хода `turn` кратен 3 (плановая проверка), ИЛИ
- разрешённое действие было «Осмотреться» или «Отдохнуть»
  (дополнительная проверка за возню и шум).

Проверка НЕ выполняется: на глубине 0 (у входа безопасно); если в текущей
комнате уже есть существо.

### 7.2. Вероятность и зависимость от глубины

Бросок d20; встреча происходит при результате
`<= 1 + floor(depth / 4)`, но не больше 5:

| Глубина | Порог | Вероятность |
|---|---|---|
| 1-3 | 1 | 5 процентов |
| 4-7 | 2 | 10 процентов |
| 8-11 | 3 | 15 процентов |
| 12-15 | 4 | 20 процентов |
| 16+ | 5 | 25 процентов |

### 7.3. Разрешение

При срабатывании в текущей комнате появляется существо: строка
`clamp(d6 + floor(depth / 2), 1, 12)` по таблице 5.1, реакция 2d6 без
модификаторов. Далее — обычные правила встреч (раздел 5).

## 8. Баланс

Целевая длительность партии: 30-60 ходов (медианный пресет `medium` —
около 35-45). Ниже арифметика, на которой подкручены числа.

### 8.1. Средний прирост progress

Ожидание на одну открытую комнату (глубина < 6):

- событие: книга `+4 * 1/12 = +0.33`; шёпот `+1 * (2/6) * (1/12) = +0.03`;
  дезинформация `-2 * 1/12 = -0.17`; итого около `+0.20`;
- осмотр: особая локация с шансом около 0.27 (5-6 особых строк в любом
  20-строчном окне из 30) даёт `0.27 * 3 = +0.80`; обычная
  `0.73 * 0.30 * 1 = +0.22`; итого около `+1.02`;
- разговоры: около 0.5 встречи на комнату (события 4/12 плюс бродячие),
  из них говоримых около 75 процентов, знающих 5/12, успех около 45
  процентов: `0.5 * 0.75 * 0.45 * (5/12) * 3` — около `+0.21`;
- карточки и добыча — резерв около +0.1.

Итого около +1.4-1.5 progress на комнату при ~2.3 хода на комнату (переход
1, осмотр 1, накладные бои/разговоры/переходы ~0.3): **около 0.6 progress
за ход**; на глубине >= 6 бонусы книги и особых локаций поднимают темп до
**около 0.75 за ход**.

### 8.2. Длительность по пресетам

| Пресет | Нужно набрать | Ходы на набор | Возврат | Итого |
|---|---|---|---|---|
| `easy` (10, глубина 3) | 7 | ~12 | ~3 | **~15-20** |
| `medium` (20, глубина 6) | 17 | ~28-32 | ~6 | **~35-45** |
| `hard` (30, глубина 10) | 27 | ~40-45 (часть на темпе 0.75) | ~10 | **~50-60** |

`easy` сознательно короче окна — обучающая партия; `medium` попадает в
середину окна; `hard` — у верхней границы.

### 8.3. Бои и урон против hp

Партия `medium`, ~40 ходов, ~14 открытых комнат:

- встречи: событийные `14 * 4/12 = 4.7`; бродячие: ~28 проверок
  (плановые 40/3 плюс осмотры и отдыхи) при среднем шансе ~10 процентов
  дают ~2.5; всего **~7 встреч**;
- из них боёв: изначально hostile ~8 процентов, опасные встречи (строка 8
  событий, hostile с шансом 15/36), деградации разговоров и атаки по
  выбору игрока — суммарно **~2 боя за партию**;
- урон за бой: средний враг середины таблицы (hp 6, урон 2-3) умирает за
  ~2 раунда (средний удар игрока 3.5), игрок получает ~2 ответа — **~5-6
  урона за бой**;
- прочий урон: феномены ~2, провалы бегства ~2; итого за партию **~14-16
  урона** против 20 hp плюс лечение (бинты ~1-2 штуки по +4, отдых +2 за
  ход) — суммарно ~28-30 эффективных hp.

Запас прочности около двукратного: смерть — результат серии неудач на
глубине (враги с уроном 4-5), а не нормы. Это целевое ощущение.

### 8.4. Ручки подкрутки

Если плейтест покажет выход за окно 30-60, крутить строго в этом порядке:

1. длительность велика — «Книга по теме» +5/+6 вместо +4/+5;
2. длительность мала — осмотр особой локации +2/+3 вместо +3/+4;
3. слишком смертельно — `FLEE_DC` 8 вместо 10;
4. слишком безопасно — вероятности бродячих встреч +5 процентных пунктов
   на всех глубинах.

Менять по одной ручке за итерацию.

## 9. Edge cases

1. **Повторный вход в комнату.** Локация, деталь и событие не
   перегенерируются и не повторяются; осмотр одноразовый навсегда;
   живое существо встречает игрока с сохранённой реакцией; бродячая
   встреча возможна по обычным правилам таймера.
2. **Возврат на глубину 0 без выполненной цели.** Ничего не происходит;
   вход — обычная комната. Покинуть библиотеку ни с чем можно только
   кнопкой «Сдаться».
3. **Переполнение таблиц.** Локации и детали: итог больше 30 считается 30.
   События с бонусом подсказки: итог больше 12 считается 12. Существа:
   `d6 + floor(depth/2)` зажимается в 1..12. Реакция ниже 2 — hostile.
4. **Победа и смерть в один ход.** Проверка смерти всегда выполняется
   раньше проверки победы (шаги 3-4 в 2.3); при любой неоднозначности
   смерть приоритетна. Фактически совпадение невозможно: перемещение не
   наносит урона, а урон не перемещает.
5. **Лимит инвентаря.** 6 слотов. Если предмет появился, а места нет — он
   остаётся лежать в комнате и автоматически подбирается при следующем
   входе в неё (или сразу после освобождения слота, если игрок в этой
   комнате).
6. **Подбор предметов.** Всегда автоматический при появлении предмета в
   комнате с игроком и при входе в комнату с лежащим предметом (если есть
   место). Отдельной кнопки подбора нет.
7. **Исчерпание заглушек.** Невозможно: гарантия фронтира (3.2 шаг 5).
8. **Переполнение полосы глубины.** Больше 10 узлов на одной глубине не
   создаётся (3.2 шаг 3); направления выходов перенаправляются или выход
   не создаётся. Гарантия фронтира при заполненной полосе уходит глубже.
9. **Бегство без цели.** Невозможно: `lastRoom` существует всегда, кроме
   старта во входе, где hostile существ не бывает (на глубине 0 нет ни
   бродячих встреч, ни события у входа).
10. **Дубли пассивных предметов.** Второй латунный нож не усиливает урон
    (эффект не суммируется), но занимает слот и может быть запасом.
11. **Блуждание и возврат домой.** Движение строго вверх не увеличивает
    `wanderCount`: возврат к входу с любой глубины бесплатен по progress.
12. **Progress ниже нуля и hp выше максимума.** Невозможны: пол 0 и
    потолок 20 применяются при каждом изменении.
13. **Детерминизм.** Один seed и одинаковая последовательность действий
    игрока дают одинаковую партию. Все случайные решения берутся только
    из единственного потока mulberry32 в порядке, заданном псевдокодом
    раздела 10. Автосейв сохраняет состояние RNG.

## 10. Псевдокод ключевых процедур

Псевдокод нормативен в части порядка бросков и ветвлений; имена —
ориентир для кода. `rng` — единственный поток mulberry32; `d6()`, `d10()`,
`d12()`, `d20()`, `roll2d6()` читают из него по одному (2d6 — два чтения).

```js
const SPECIAL_ROWS = [4, 8, 12, 16, 20, 24, 27, 30];
const KNOWING_ROWS = [3, 6, 9, 10, 12];
const MUTE_ROWS = [2, 5, 11];

function generateRoom(stub) {
  const d = stub.depth;
  const locRow = Math.min(d20() + d, 30);            // 1. локация
  const detRow = Math.min(d20() + d, 30);            // 2. деталь
  const room = openStub(stub, locRow, detRow);       // заглушка -> комната
  room.special = SPECIAL_ROWS.includes(locRow);

  const exitRoll = d6();                             // 3. выходы
  const nExits = exitRoll === 1 ? 0 : (exitRoll <= 4 ? 1 : 2);
  for (let i = 0; i < nExits; i++) {
    let dir = (d10() <= 7) ? d + 1 : d;              // 70/30 вглубь/вбок
    if (stripeFull(dir)) dir = (dir === d + 1) ? d : d + 1;
    if (!stripeFull(dir)) addStub(room, dir);        // обе полны — пропуск
  }

  resolveEvent(room, stub.hinted ? 3 : 0);           // 4. событие

  if (countStubs(graph) === 0) {                     // 5. гарантия фронтира
    let dd = d + 1;
    while (stripeFull(dd)) dd++;
    addStub(room, dd);
  }
  return room;
}

function resolveEvent(room, bonus) {
  const roll = Math.min(d12() + bonus, 12);
  if (roll <= 3) return;                                       // тишина
  if (roll === 4) return addProgress(-2);                      // дезинформация
  if (roll <= 7) return spawnEncounter(room, 0);               // встреча
  if (roll === 8) return spawnEncounter(room, -3);             // опасная
  if (roll === 9) {                                            // феномен
    const f = d6();
    if (f <= 2) return addProgress(1);
    if (f <= 4) {
      let dir = (d10() <= 7) ? room.depth + 1 : room.depth;
      if (stripeFull(dir)) dir = (dir === room.depth + 1) ? room.depth : room.depth + 1;
      if (!stripeFull(dir)) addStub(room, dir);
      return;
    }
    player.hp -= 2; checkDeath(); return;
  }
  if (roll <= 11) return spawnItem(room, d6());                // находка
  addProgress(room.depth >= 6 ? 5 : 4);                        // книга по теме
}

function spawnEncounter(room, reactionMod) {
  if (room.creature) return;
  const row = Math.max(1, Math.min(d6() + Math.floor(room.depth / 2), 12));
  const r = roll2d6() + reactionMod;
  const reaction = r <= 3 ? 'hostile' : r <= 6 ? 'wary'
                 : r <= 9 ? 'neutral' : 'friendly';
  room.creature = makeCreature(row, reaction);     // hp, dmg из таблицы 5.1
}

function encounterRound() {                        // действие «Сражаться»
  const c = currentRoom().creature;
  c.hp -= d6() + (hasItem('paper_knife') ? 2 : 0); // игрок бьёт, промахов нет
  if (c.hp <= 0) {                                 // смерть врага, добыча
    const loot = d6();
    if (loot >= 4) spawnItem(currentRoom(), d6());
    if (loot === 6) addProgress(1);
    currentRoom().creature = null;
  } else if (c.reaction !== 'hostile') {
    c.reaction = 'hostile';                        // в этом раунде не отвечает
  } else {
    dealToPlayer(c.dmg);                           // ответ врага (оберег: 0)
  }
  endTurn({ extraCheck: false });
}

function talk() {                                  // действие «Говорить»
  const c = currentRoom().creature;                // не hostile, не mute
  const mod = { friendly: 4, neutral: 0, wary: -4 }[c.reaction];
  if (d20() + mod >= 12) {
    if (!c.rewardGiven) {
      if (c.knowing) addProgress(3);
      else if (countStubs(graph) > 0) giveHint();  // stub.hinted = true
      else addProgress(1);
      c.rewardGiven = true;
    }
    c.reaction = improve(c.reaction);              // wary->neutral->friendly
  } else {
    c.reaction = worsen(c.reaction);               // ...->hostile, без удара
  }
  endTurn({ extraCheck: false });
}

function flee() {                                  // действие «Бежать»
  const c = currentRoom().creature;
  const auto = consumeIfActive('lantern');
  if (auto || d20() >= 10) {
    moveTo(state.lastRoom);                        // существо остаётся
  } else {
    dealToPlayer(c.dmg);                           // свободная атака
  }
  endTurn({ extraCheck: false });
}

function checkWin() {
  return state.progress >= preset.threshold
      && state.maxDepth >= preset.minDepth
      && currentRoom().id === ENTRANCE_ID
      && player.hp > 0;
}

// --- вспомогательные, нормативные по порядку проверок ---

function endTurn(opts) {
  state.turn += 1;
  if (player.hp <= 0) return showScreen('lose');
  if (checkWin()) return showScreen('win');
  const due = state.turn % 3 === 0 || opts.extraCheck; // осмотр/отдых: true
  if (due && currentRoom().depth > 0 && !currentRoom().creature) {
    const chance = Math.min(1 + Math.floor(currentRoom().depth / 4), 5);
    if (d20() <= chance) spawnEncounter(currentRoom(), 0);
  }
  autosave();
}

function moveTo(room) {                            // и клик по узлу, и бегство
  const from = currentRoom();
  if (room.visited && room.depth >= from.depth) {
    state.wanderCount += 1;
    if (state.wanderCount >= 5) { addProgress(-1); state.wanderCount = 0; }
  }
  if (!room.visited) state.wanderCount = 0;
  state.lastRoom = from;
  setCurrentRoom(room);
  room.visited = true;
  state.maxDepth = Math.max(state.maxDepth, room.depth);
  pickupItemsIfSpace(room);                        // автоподбор
}

function addProgress(n) {
  state.progress = Math.max(0, state.progress + n);
  if (n > 0) state.wanderCount = 0;
}
```

Переход кликом по заглушке: `generateRoom(stub)`, затем `moveTo(room)`,
затем `endTurn({extraCheck: false})`. Переход в открытую комнату:
`moveTo(room)`, затем `endTurn({extraCheck: false})`. «Осмотреться» и
«Отдохнуть» вызывают `endTurn({extraCheck: true})`.
