# Промпт: прототип «Стигийская библиотека» — один index.html за один проход

Ты — старший инженер. Твоя задача — за один проход, без уточняющих вопросов,
написать полностью рабочий прототип соло-игры «Стигийская библиотека»
(depth crawl по мотивам The Stygian Library, Emmy Allen) в виде одного файла
`index.html` на vanilla JS + SVG + CSS. Этот промпт — единственный и полный
источник требований: все правила, все игровые данные, вся архитектура и вся
спецификация интерфейса собраны ниже и согласованы между собой. Ничего не
выдумывай сверх написанного и ничего из написанного не меняй.

TL;DR задачи:

1. Один файл `prototype/index.html`, запускается двойным кликом, полностью оффлайн.
2. Пошаговый соло depth crawl: карта-граф растёт вниз, глубина = сложность.
3. Вся случайность — единственный seeded-поток mulberry32; автосейв в localStorage.
4. Все таблицы данных (30 локаций, 30 деталей, события, существа, предметы) — в этом промпте, инлайн.
5. Перед сдачей самостоятельно прогони чеклист приёмки (раздел 9) и все сценарии самопроверки (раздел 10).

## 1. Контекст: что это за игра

The Stygian Library (Emmy Allen, 2018) — OSR-приключение про бесконечную
междумировую библиотеку, в которую прорастают все достаточно старые земные
библиотеки. Туда идут не «зачищать данж», а искать ответ на конкретный вопрос.
Карта не нарисована заранее: библиотека генерируется по мере продвижения.

Движок называется depth crawl. Состояние мира — одно число Depth (глубина,
вход = 0) плюс растущий point-crawl граф открытых комнат. Шаг в неисследованный
проход порождает комнату тремя бросками: `d20 + depth` по таблице локаций,
`d20 + depth` по таблице деталей, бросок по таблице событий. Таблицы локаций и
деталей отсортированы от обыденного к невозможному, поэтому модификатор глубины
сам стратифицирует мир: у поверхности — читальные залы, в глубине — невозможная
архитектура и опасные обитатели. Открытые комнаты фиксируются навсегда.

Цель — не точка на карте, а счётчик Progress: разговоры со знающими существами,
осмотры и найденные книги двигают его к порогу исследовательского вопроса.
Победа: набрать порог, побывать на требуемой глубине и вернуться к входу живым.
Поражение: HP опустились до 0. Игрок один, интерфейс на русском, боёвка
ультра-лёгкая, партия — примерно 25-60 ходов в зависимости от пресета.

## 2. Деливерабл

- Ровно один файл: `prototype/index.html`. Если файловая система тебе
  недоступна — выдай полный код файла одним блоком кода без сокращений.
- Критерий запуска: пользователь делает двойной клик по файлу в проводнике,
  файл открывается в Chrome или Edge без сети и игра полностью работает.
- Никаких других файлов, никаких внешних ресурсов (CDN, шрифты, картинки,
  иконки, запросы в сеть). Единственное допустимое вхождение подстроки `http`
  в файле — константа `const SVG_NS = 'http://www.w3.org/2000/svg'`,
  используемая только в `document.createElementNS` при сборке узлов и рёбер
  карты. Атрибут `xmlns` у инлайнового SVG в разметке не указывается —
  в HTML он не нужен. Никаких иных URL нигде, включая комментарии.
- Никаких инструментов сборки, фреймворков и библиотек.

## 3. Зафиксированные технические решения

Эти восемь пунктов не обсуждаются и не оспариваются; всё остальное в промпте
спроектировано строго в их рамках.

1. **Технология.** Один файл `index.html` — vanilla JS + SVG + CSS. Без
   фреймворков, без сборки, без внешних ресурсов (CDN, шрифты, картинки,
   запросы в сеть). Запускается двойным кликом, работает оффлайн в Chrome/Edge.
2. **Язык.** Игра пошаговая, соло, интерфейс на русском языке. Идентификаторы
   в коде и ключи данных — английские. Эмодзи запрещены везде: и в текстах,
   и в UI, и в коде, и в комментариях. Иконки — только SVG-примитивы или буквы.
3. **Карта.** Point-crawl граф: узлы-комнаты, рёбра-проходы. Глубина (Depth) —
   вертикальная ось: вход (depth 0) сверху, карта растёт вниз. Узлы каждой
   глубины лежат в своей горизонтальной полосе.
4. **Перемещение.** Клик по соседнему узлу. Неисследованные выходы видны как
   узлы-заглушки со знаком вопроса. Переход в заглушку генерирует комнату:
   бросок `d20 + depth` по таблице локаций, `d20 + depth` по таблице деталей,
   затем бросок по таблице событий. Открытые комнаты фиксируются навсегда и
   при повторном посещении не перегенерируются.
5. **Таблицы.** Локации и детали — ровно по 30 строк, отсортированы от
   обыденного к странному. Результат броска выше 30 считается ровно 30
   (явное правило clamp).
6. **Цель партии.** Исследовательский вопрос с порогом Progress (3 пресета
   сложности) и минимальной глубиной. Победа = набрать порог, побывав на
   нужной глубине, и вернуться ко входу живым. Поражение = HP опустились до 0.
7. **Случайность и сейв.** Seeded RNG (mulberry32), seed задаётся на старте.
   Автосейв в localStorage, кнопка новой игры.
8. **Объём.** Ориентир 1500-2500 строк в index.html. Простота важнее фич:
   лучше меньше механик, но работающих. Боёвка ультра-лёгкая.

## 4. Правила игры (нормативно)

Все числа этого раздела обязательны к реализации точно как написано.
«Бросок dN» — равновероятное целое 1..N из единственного seeded-потока
mulberry32 (раздел 6); `rollRange(n)` — равновероятное целое 1..n из того же
потока (одно чтение, даже при n = 1). Порядок потребления бросков фиксирован
псевдокодом раздела 4.11; никакой код рендера, UI или журнала не потребляет
броски из этого потока. Детерминизм обязателен: один seed и одна
последовательность действий игрока дают одинаковую партию вплоть до каждого
броска.

### 4.0. Сводка констант

| Константа (id в коде) | Значение | Смысл |
|---|---|---|
| `HP_MAX` | 20 | максимум и стартовое значение hp |
| `START_PROGRESS` | 3 | стартовый progress |
| `INVENTORY_MAX` | 6 | слотов инвентаря |
| `TALK_DC` | 12 | сложность проверки «Говорить» (d20 + мод реакции) |
| `FLEE_DC` | 10 | сложность проверки «Бежать» (d20, без модификаторов) |
| `ENCOUNTER_PERIOD` | 3 | период плановой проверки бродячей встречи (ходы) |
| `WANDER_LIMIT` | 5 | счётчик блуждания, при котором списывается 1 progress |
| `DEEP_BONUS_DEPTH` | 6 | глубина первой ступени «бонуса глубины» (4.3, 4.5, 4.7) |
| `DEEP_BONUS_DEPTH_2` | 10 | глубина второй ступени «бонуса глубины» (4.3, 4.5, 4.7) |
| `REST_HEAL` | 2 | восстановление hp действием «Отдохнуть» |
| `MAX_NODES_PER_DEPTH` | 10 | максимум узлов (комнат и заглушек) на одной глубине |
| `TABLE_ROWS` | 30 | строк в таблицах локаций и деталей |
| `SPECIAL_ROWS` | 4, 8, 12, 16, 20, 24, 27, 30 | особые строки таблицы локаций |

### 4.1. Персонаж и старт

Персонаж один, без классов и листа характеристик:

- `hp` — очки здоровья. Старт 20, максимум 20, выше 20 не поднимается.
  При `hp <= 0` — немедленное поражение (4.9).
- `progress` — счётчик приближения к ответу. Старт 3. Минимум 0, верхней
  границы нет.
- `inventory` — список предметов, максимум 6 слотов, 1 предмет = 1 слот.
  Старт: пусто.
- Счётчики партии: `turn` (номер хода, старт 0), `depth` (глубина текущей
  комнаты, старт 0), `maxDepth` (наибольшая посещённая глубина, старт 0),
  `wanderCount` (счётчик блуждания, старт 0).

Три пресета исследовательского вопроса (на стартовом экране выбирается ровно
один, по умолчанию первый):

| id | Имя | Пример вопроса | Порог progress | Мин. глубина |
|---|---|---|---|---|
| `easy` | Забытый рецепт | Каков был рецепт чернил, которыми написан Велленхольмский кодекс? | 16 | 4 |
| `medium` | Утраченная биография | Кем на самом деле была картограф Ирен Вольц и куда она исчезла? | 20 | 6 |
| `hard` | Запретный гримуар | Что написано на последней странице Гримуара Бессонных и почему её нельзя читать вслух? | 30 | 10 |

Порог и минимальная глубина фиксируются на всю партию.

Старт партии (кнопка «Войти в библиотеку»):

1. Инициализируется RNG из seed. Пустое поле seed — случайное целое
   1..999999; оно становится seed партии и показывается в статусе. Детали
   потока — раздел 6.
2. Создаётся узел входа: id 0, depth 0, название «Вход», тег `entrance`,
   вне таблиц, без события и без особости; осмотр доступен по правилам
   обычной локации.
3. К входу добавляются ровно 2 заглушки глубины 1 (без бросков направления).
4. Игрок помещается во вход. `turn = 0`, `hp = 20`, `progress = 3`.

Игрок видит на старте: карту (вход + 2 заглушки), панель статуса
(hp 20/20, глубина 0, progress 3/порог, ход 0, seed), пустой блок инвентаря
(6 слотов; предметы в нём кликабельны — раздел 4.8), описание входа,
кнопки «Осмотреться» и «Сдаться», журнал с записью о начале партии.
Игрок НЕ видит содержимое заглушек до их открытия. В журнал честно пишутся
все броски, для которых в 7.7 задан шаблон: локация, деталь, событие,
феномен, реакция, осмотр, бой, добыча, разговор, бегство, бродячая встреча.
Служебные броски структуры (число выходов, направление заглушки, выбор
строки существа, выбор предмета, выбор заглушки-подсказки) отдельно не
логируются.

### 4.2. Структура хода

Верхний уровень — четыре экрана: `start`, `game`, `win`, `lose`. Внутри
`game` состояние определяется парой «существо в текущей комнате; его
реакция». Существо в комнате — не более одного. Состояния: `idle`
(существа нет), `friendly`, `neutral`, `wary`, `hostile`.

Матрица доступности действий (да/нет):

| Действие | idle | friendly | neutral | wary | hostile |
|---|---|---|---|---|---|
| Перейти в открытую соседнюю комнату (клик по узлу) | да | да | да | да | нет |
| Перейти в соседнюю заглушку (клик по узлу) | да | да | да | нет | нет |
| Осмотреться (если комната ещё не осмотрена) | да | да | да | нет | нет |
| Отдохнуть (если hp < 20, существа нет и depth > 0) | да | нет | нет | нет | нет |
| Говорить (если существо не бессловесное) | нет | да | да | да | нет |
| Сражаться | нет | да | да | да | да |
| Бежать | нет | нет | нет | нет | да |
| Использовать предмет (клик по предмету в инвентаре) | да | да | да | да | да |
| Сдаться (кнопка, с инлайн-подтверждением) | да | да | да | да | да |

Перемещение — кликом по соседнему узлу карты; остальные действия — кнопками.
Недоступные действия не показываются вовсе (не disabled). Кнопок действий
одновременно не больше четырёх, «Сдаться» всегда последняя. Эта граница
достигается ровно в состояниях friendly/neutral с неосмотренной комнатой:
«Осмотреться», «Говорить», «Сражаться», «Сдаться» (порядок кнопок — 7.2).

Стоимость действий:

| Действие | Стоимость |
|---|---|
| Перейти (в открытую комнату или в заглушку) | 1 ход |
| Осмотреться | 1 ход |
| Отдохнуть | 1 ход |
| Говорить | 1 ход |
| Сражаться (один раунд) | 1 ход |
| Бежать (одна попытка) | 1 ход |
| Использовать предмет | 0 ходов (свободное действие) |
| Подбор предмета | 0 ходов (автоматический) |
| Сдаться | завершает партию |

Порядок разрешения каждого действия стоимостью 1 ход:

1. Действие исполняется полностью (включая ответ врага в раунде боя или
   свободную атаку при провале бегства).
2. `turn += 1`.
3. Проверка смерти: если `hp <= 0` — экран `lose`, дальнейшие шаги не выполняются.
4. Проверка победы: если игрок в узле входа и условия победы выполнены (4.9) —
   экран `win`, дальнейшие шаги не выполняются.
5. Проверка бродячей встречи (4.10), если положено по таймингу.
6. Автосейв в localStorage. Сейв обязан включать позицию RNG-потока (seed и
   счётчик чтений), чтобы загрузка продолжала ту же последовательность
   бросков; формат сейва — раздел 6.

Свободные действия (предметы) не двигают `turn` и не вызывают проверок
бродячих встреч, но тоже завершаются проверкой смерти/победы и автосейвом;
при срабатывании смерти или победы автосейв и рендер не выполняются
(сейв уже стёрт в `showEnd`, см. сцепку в 4.11).

### 4.3. Действия «Осмотреться» и «Отдохнуть»

**Осмотреться** — один раз на комнату (`room.searched`), запрещено при
существе wary/hostile:

- Особая локация (`locRow` входит в `SPECIAL_ROWS`): `progress += 3`
  (на глубине >= 6: `+= 4`; на глубине >= 10: `+= 5`); затем бросок d20:
  при 15-20 в комнате появляется предмет (бросок d6 по таблице находок 4.5).
- Обычная локация: бросок d20: 1-8 — ничего; 9-14 — `progress += 1`
  (на глубине >= 6: `+= 2`); 15-20 — предмет (d6 по таблице находок).

После разрешения комната помечается осмотренной навсегда. Осмотр всегда
вызывает дополнительную проверку бродячей встречи.

**Отдохнуть** — доступно при отсутствии существа, `hp < 20` и не в узле
входа (depth > 0). Эффект: `hp += 2` (не выше 20). Всегда вызывает
дополнительную проверку бродячей встречи, причём отдых «шумит»: порог этой
проверки равен `min(3 + floor(depth / 4), 7)` вместо обычного (4.10).

### 4.4. Генерация комнаты при переходе в заглушку

Заглушка — узел с известной глубиной без содержимого. Клик по заглушке,
соседней с текущей комнатой, выполняет `generateRoom` и перемещает игрока
в созданную комнату (1 ход). Для заглушки глубины `d` строго по порядку:

1. **Локация**: `locRow = d20 + d`; результат больше 30 считается ровно 30
   (clamp). Строка таблицы LOCATIONS даёт название, описание, тег (набор
   тегов задан в разделе 5) и особость (`special = SPECIAL_ROWS.includes(locRow)`).
2. **Деталь**: `detRow = d20 + d`, тот же clamp до 30. Строка DETAILS
   добавляет предложение-деталь.
3. **Выходы**: бросок d6: 1 — 0 новых заглушек (тупик); 2-4 — 1 заглушка;
   5-6 — 2 заглушки. Для каждой заглушки отдельный бросок d10 на направление:
   1-7 — вглубь (глубина `d + 1`); 8-10 — вбок (глубина `d`). Ограничение
   полосы: если на выбранной глубине уже 10 узлов (комнат и заглушек
   суммарно), направление заменяется на альтернативное; если обе полосы
   заполнены — заглушка не создаётся.
4. **Событие**: бросок `d12 + floor(d / 8)` по таблице событий (4.5); итог
   выше 12 считается 12. Если заглушка была «многообещающей» (hinted,
   см. 4.6), к броску дополнительно прибавляется 3 (тот же clamp до 12).
5. **Гарантия фронтира**: если после шагов 3-4 во всём графе не осталось ни
   одной заглушки, текущая комната принудительно получает одну заглушку
   глубины `d + 1` (если полоса `d + 1` заполнена — `d + 2`, и так далее).

Комната записывается в граф навсегда: повторное посещение никогда не
перегенерирует ни локацию, ни деталь, ни событие. Дубликаты строк локаций
в разных комнатах допустимы и нормальны.

Стратификация: на глубине `d` доступно окно строк `1 + d .. 20 + d` с clamp
до 30; начиная с глубины 29 любой бросок даёт строку 30 — это допустимо.

Граф — дерево с корнем во входе: каждая новая заглушка соединяется ребром
ровно с одной родительской комнатой (заглушка «вбок» — тоже ребро к своему
родителю, просто на той же глубине), рёбра никогда не удаляются, рёбра между
двумя уже существующими узлами никогда не добавляются, узлы не сливаются,
циклов нет. Следствия (обязательны): из любой комнаты есть путь до входа;
перемещение по открытым комнатам не запрещается ничем, кроме hostile (откуда
всегда доступно повторяемое «Бежать»); тупик не опасен; библиотека не может
закончиться (гарантия фронтира).

### 4.5. События

Бросок события — `d12 + floor(depth / 8)`, итог выше 12 считается 12;
глубже — реже тишина и чаще «Книга по теме», частота встреч и дезинформации
не меняется. Бросается один раз при генерации комнаты, при повторных
посещениях не перебрасывается. «Итог» — значение после модификатора и clamp:

| Итог | Событие | Эффект |
|---|---|---|
| 1-3 | Тишина | Ничего; в журнал — строка таблицы UI_SILENCE (раздел 5) с индексом `room.id % 10`. Выбор строки НЕ потребляет бросков RNG-потока. |
| 4 | Дезинформация | `progress -= 2` (не ниже 0). |
| 5-7 | Встреча | Существо (4.6), бросок реакции 2d6 без модификаторов. |
| 8 | Опасная встреча | Существо (4.6), бросок реакции 2d6 с модификатором -3. |
| 9 | Феномен | Бросок d6 по суб-таблице феноменов. |
| 10-11 | Находка | Предмет: бросок d6 по таблице находок. |
| 12 | Книга по теме | `progress += 4` (на глубине >= 6: `+= 5`; на глубине >= 10: `+= 6`). |

Суб-таблица феноменов (d6):

| d6 | Феномен | Эффект |
|---|---|---|
| 1-2 | Шёпот стеллажей | `progress += 1`. |
| 3-4 | Сдвиг пространства | Комната получает 1 дополнительную заглушку: направление по обычному правилу (d10: 1-7 вглубь, 8-10 вбок; с ограничением полосы). |
| 5-6 | Пыльная мгла | `hp -= 2`, немедленная проверка смерти. Закладка-оберег НЕ применяется (урон не от существа). |

Таблица находок (d6) — используется событиями 10-11, осмотром (4.3) и
добычей (4.7). Предмет появляется в комнате и подбирается автоматически:

| d6 | Предмет (id) | Тип | Эффект |
|---|---|---|---|
| 1-2 | Бинты (`bandage`) | используемый | `hp += 4` (не выше 20). Расходуется. |
| 3 | Латунный нож для бумаг (`paper_knife`) | пассивный | +2 к урону игрока, пока в инвентаре. Не суммируется от двух ножей. |
| 4 | Каталожная карточка (`catalog_card`) | используемый | `progress += 2`. Расходуется. |
| 5 | Фонарь с маслом (`lantern`) | используемый | Следующая попытка «Бежать» автоматически успешна. Расходуется при активации. |
| 6 | Закладка-оберег (`ward_bookmark`) | используемый | Следующий урон ОТ СУЩЕСТВА по игроку становится 0. Расходуется при активации. |

Правила обращения с предметами (подбор, использование, активации) — раздел 4.8.

### 4.6. Встречи

Источники существ: события 5-8 и бродячие встречи (4.10). Существо появляется
в текущей комнате; если в комнате уже есть существо, новое не появляется.
Существо привязано к комнате и сохраняется в ней с текущей реакцией, пока не
убито: уйдя и вернувшись, игрок застанет его таким же. Существо и его текущая
реакция всегда видны игроку: отдельной строкой в блоке текущей комнаты (имя
существа, его hp и реакция по-русски) и записью в журнале в момент появления
и при каждой смене реакции.

Выбор существа: строка `clamp(d6 + floor(depth / 2), 1, 12)` по таблице
существ (статы здесь, описания — в разделе 5.6):

| Строка | Существо (id) | hp | Урон | Знающее | Бессловесное |
|---|---|---|---|---|---|
| 1 | Заблудившийся читатель (`lost_reader`) | 3 | 1 | нет | нет |
| 2 | Рой книжной моли (`moth_swarm`) | 2 | 1 | нет | да |
| 3 | Служитель-новичок (`novice_clerk`) | 4 | 1 | да | нет |
| 4 | Оригами-голем (`origami_golem`) | 5 | 2 | нет | нет |
| 5 | Пылевой элементаль (`dust_elemental`) | 6 | 2 | нет | да |
| 6 | Библиотекарь серого ордена (`grey_librarian`) | 5 | 2 | да | нет |
| 7 | Ожившая книга-хищник (`predator_book`) | 7 | 3 | нет | нет |
| 8 | Чернильный призрак (`ink_ghost`) | 6 | 3 | нет | нет |
| 9 | Библиотекарь чёрного ордена (`black_librarian`) | 8 | 3 | да | нет |
| 10 | Скелет-архивариус (`skeleton_archivist`) | 9 | 3 | да | нет |
| 11 | Страж запретного отдела (`vault_warden`) | 12 | 4 | нет | да |
| 12 | То-Что-Читает (`that_which_reads`) | 14 | 5 | да | нет |

Бросок реакции: 2d6 (два чтения из потока) плюс модификатор источника
(событие 8: -3; иначе 0):

| Итог | Реакция |
|---|---|
| 3 и меньше | hostile (враждебно) |
| 4-6 | wary (настороженно) |
| 7-9 | neutral (нейтрально) |
| 10 и больше | friendly (дружелюбно) |

Поведение по реакциям:

- **hostile**: блокирует перемещение и осмотр; доступны только «Сражаться»,
  «Бежать», предметы, «Сдаться». Существо наносит урон только в ответ: на
  раунд боя и на провал бегства.
- **wary**: не атакует; запрещает осмотр и переходы в заглушки; в открытые
  комнаты уйти можно. Доступны «Говорить» и «Сражаться».
- **neutral**: ничего не запрещает, кроме отдыха. Доступны «Говорить» и «Сражаться».
- **friendly**: как neutral, но проверка разговора с бонусом +4.

**Говорить** (существо не hostile и не бессловесное). Проверка
`d20 + мод >= 12`, мод: friendly +4, neutral 0, wary -2. Порог успеха
разговора виден игроку заранее — в строке существа в `#room-panel` (7.2).

- Успех: реакция улучшается на одну ступень (wary -> neutral -> friendly;
  выше friendly не растёт). Если награда с этого существа ещё не получена
  (`rewardGiven = false`): знающее — `progress += 3`; не знающее — подсказка
  (см. ниже), а если все заглушки графа уже hinted — `progress += 1`
  (вместо подсказки). После выдачи
  `rewardGiven = true`; повторные успехи дают только улучшение реакции.
- Провал: реакция ухудшается на ступень (friendly -> neutral -> wary ->
  hostile). Ставшее hostile существо в момент провала урон не наносит.

**Подсказка**: случайная заглушка графа помечается «многообещающей»
(`stub.hinted = true`). Кандидаты — не-hinted заглушки, соседние с текущей
комнатой; если таких нет — все не-hinted заглушки графа (случай «все
заглушки уже hinted» до выбора не доходит: вместо подсказки начисляется
`progress += 1`, см. выше). Выбор: кандидаты сортируются по id по
возрастанию, берётся элемент с индексом `rollRange(n) - 1`, где n — число
кандидатов. При открытии hinted-заглушки бросок события получает +3 поверх
глубинного модификатора `floor(depth / 8)` (итог выше 12 считается 12).
Одна заглушка не помечается дважды: кандидаты всегда фильтруются по
`!hinted`. В журнал пишется, что направление указано; на карте
hinted-заглушка подсвечивается (спецификация подсветки — раздел 7).

**Сражаться** (один раунд = один ход, промахов нет):

1. Игрок наносит урон: `d6` (+2, если в инвентаре латунный нож). Урон
   вычитается из hp существа.
2. Если существо погибло (`hp <= 0`) — добыча (см. ниже), раунд окончен.
3. Если существо было не hostile — оно становится hostile и в этом раунде
   не отвечает.
4. Если существо hostile — оно отвечает: игрок получает фиксированный «Урон»
   из строки существа (активная закладка-оберег обнуляет урон и расходуется).
   Проверка смерти.

Атака по friendly/neutral/wary разрешена и немедленно делает существо hostile
(шаг 3). Никаких особых штрафов за убийство кого бы то ни было, включая
библиотекарей, нет.

**Добыча** (существо удаляется из комнаты навсегда): бросок d6:
1-3 — ничего; 4-5 — предмет (d6 по таблице находок); 6 — предмет (d6 по
таблице находок) И `progress += 1`.

**Бежать** (только при hostile). Цель: комната, из которой игрок пришёл в
текущую (`lastRoom`, хранится в состоянии, обновляется при каждом переходе).
Защита от «пинг-понга»: если в `lastRoom` стоит существо с реакцией hostile,
целью бегства становится соседняя с текущей открытая комната без существа с
наименьшим id; если таких нет — всё же `lastRoom`. Разрешение: если
активирован фонарь — автоуспех, фонарь расходуется; иначе проверка
`d20 >= 10`. Успех: игрок перемещается в выбранную цель (существо остаётся
hostile в своей комнате). Провал: свободная атака — игрок получает
фиксированный урон существа (закладка-оберег применима), остаётся на месте,
проверка смерти. Попытку можно повторять каждый ход без ограничений.

### 4.7. Progress

Источники (полный список):

| Источник | Очки |
|---|---|
| Книга по теме (событие 12) | +4; на глубине >= 6: +5; на глубине >= 10: +6 |
| Первый успешный разговор со знающим существом | +3 |
| Осмотр особой локации (строки 4, 8, 12, 16, 20, 24, 27, 30) | +3; на глубине >= 6: +4; на глубине >= 10: +5 |
| Осмотр обычной локации, d20 = 9-14 | +1; на глубине >= 6: +2 |
| Феномен «Шёпот стеллажей» | +1 |
| Каталожная карточка (предмет) | +2 |
| Добыча с существа, d6 = 6 | +1 |
| Первый успешный разговор с не знающим существом, когда все заглушки уже hinted | +1 (вместо подсказки) |

Штрафы:

| Штраф | Очки | Условие |
|---|---|---|
| Дезинформация (событие 4) | -2 | при генерации комнаты |
| Блуждание | -1 | `wanderCount` достиг 5, затем счётчик обнуляется |

Правило блуждания: `wanderCount += 1` при каждом переходе в уже посещённую
комнату, глубина которой больше или равна глубине покидаемой (движение
строго вверх, к выходу, не штрафуется). Счётчик сбрасывается в 0 при
открытии новой комнаты и при любом начислении положительного progress.
Progress не опускается ниже 0.

### 4.8. Инвентарь и предметы

- Инвентарь — 6 слотов, 1 предмет = 1 слот. Дубликаты любых предметов
  допустимы и занимают слоты по отдельности.
- Подбор всегда автоматический и бесплатный (0 ходов): при появлении предмета
  в комнате с игроком и при входе в комнату с лежащим предметом. Отдельной
  кнопки подбора нет. Если все слоты заняты — предмет остаётся лежать в
  комнате и подбирается при следующем входе в неё (или сразу после
  освобождения слота, если игрок стоит в этой комнате). `pickupItems(room)`
  ничего не делает, если room — не текущая комната игрока: предмет,
  созданный событием «Находка» при открытии заглушки, подбирается вызовом
  `pickupItems` в конце `moveTo` при входе, поэтому запись «Найдено» идёт
  после записи об открытии комнаты.
- Использование предмета — клик по нему в блоке инвентаря; свободное действие
  в любой момент своего хода, в том числе в бою: 0 ходов, без проверки
  бродячей встречи, но с проверкой смерти/победы после эффекта; автосейв и
  рендер выполняются, только если ни смерть, ни победа не сработали
  (сцепка — 4.11).
- Бинты при `hp = 20` не расходуются: клик не делает ничего. Каталожная
  карточка применима всегда.
- Латунный нож — пассивный: даёт +2 к урону игрока, просто лёжа в инвентаре;
  кликом не используется; второй нож эффект не усиливает, но слот занимает.
- Активация фонаря или закладки-оберега убирает предмет из инвентаря и
  поднимает флаг (`lanternActive` / `wardActive`). Флаг расходуется при
  срабатывании: фонарь — на ближайшей попытке «Бежать» (автоуспех), закладка —
  на ближайшем уроне от существа по игроку (урон становится 0). Урон не от
  существа (пыльная мгла) закладку не расходует и не обнуляется ею.
  Одновременно может быть активен только один фонарь и одна закладка:
  повторная активация до срабатывания невозможна (кнопка не показывается).

### 4.9. Победа, поражение, сдача

**Победа** наступает, когда одновременно: `progress >= порог пресета`, И
`maxDepth >= минимальная глубина пресета`, И игрок находится в узле входа
(depth 0), И `hp > 0`. Проверка выполняется при каждом входе в узел входа И
после каждого изменения progress, пока игрок стоит во входе (в том числе от
свободного действия — каталожной карточки). При выполнении — экран `win`
немедленно, без дополнительной кнопки. Если progress упал ниже порога до
возвращения — победы нет: условие проверяется только в текущий момент.

**Поражение**: `hp <= 0` в любой момент — немедленный экран `lose`. Смерть
проверяется сразу после любого получения урона и имеет приоритет над всеми
прочими эффектами и над победой.

**Сдаться**: кнопка доступна всегда, с инлайн-подтверждением (раздел 7.6).
Партия завершается, автосейв стирается, открывается экран `start`. Это не
поражение и не победа. Стоя у входа без выполненных условий, игрок выходит
из библиотеки именно так.

### 4.10. Бродячие встречи

Проверка выполняется на шаге 5 порядка разрешения хода (4.2), если выполнено
хотя бы одно: `turn` кратен `ENCOUNTER_PERIOD` = 3 (плановая проверка) ИЛИ
разрешённое действие было «Осмотреться» или «Отдохнуть» (дополнительная
проверка). Проверка НЕ выполняется на глубине 0 и если в текущей комнате
уже есть существо.

Бросок d20; встреча происходит при результате `<= 1 + floor(depth / 4)`,
но порог не больше 5. Если разрешённым действием было «Отдохнуть»,
единственная выполняемая проверка использует повышенный порог
`min(3 + floor(depth / 4), 7)` — отдых «шумит» (4.3). Таблица ниже — для
обычного порога:

| Глубина | Порог | Вероятность |
|---|---|---|
| 1-3 | 1 | 5 процентов |
| 4-7 | 2 | 10 процентов |
| 8-11 | 3 | 15 процентов |
| 12-15 | 4 | 20 процентов |
| 16+ | 5 | 25 процентов |

При срабатывании в текущей комнате появляется существо: строка
`clamp(d6 + floor(depth / 2), 1, 12)`, реакция 2d6 без модификаторов,
далее обычные правила встреч (4.6).

### 4.11. Нормативный псевдокод

Псевдокод нормативен в части порядка бросков и ветвлений. `d6()`, `d10()`,
`d12()`, `d20()`, `rollRange(n)` читают из единственного потока по одному
значению, `roll2d6()` — два чтения.

```js
const SPECIAL_ROWS = [4, 8, 12, 16, 20, 24, 27, 30];
const KNOWING_ROWS = [3, 6, 9, 10, 12];   // знающие существа
const MUTE_ROWS = [2, 5, 11];             // бессловесные существа

function generateRoom(stub) {
  const d = stub.depth;
  const locRow = Math.min(d20() + d, 30);            // 1. локация
  const detRow = Math.min(d20() + d, 30);            // 2. деталь
  const room = openStub(stub, locRow, detRow);       // заглушка -> комната
  room.special = SPECIAL_ROWS.includes(locRow);

  const exitRoll = d6();                             // 3. выходы
  const nExits = exitRoll === 1 ? 0 : (exitRoll <= 4 ? 1 : 2);
  for (let i = 0; i < nExits; i++) {
    let dir = (d10() <= 7) ? d + 1 : d;              // 70/30 вглубь/вбок
    if (stripeFull(dir)) dir = (dir === d + 1) ? d : d + 1;
    if (!stripeFull(dir)) createStub(room, dir);     // обе полны — пропуск
  }

  resolveEvent(room, Math.floor(d / 8) + (stub.hinted ? 3 : 0)); // 4. событие
  if (state.player.hp <= 0) return null;             // смерть от события:
                                                     // шаг 5 не выполняется
  if (countStubs() === 0) {                          // 5. гарантия фронтира
    let dd = d + 1;
    while (stripeFull(dd)) dd++;
    createStub(room, dd);
  }
  return room;
}

function resolveEvent(room, bonus) {
  const roll = Math.min(d12() + bonus, 12);
  if (roll <= 3) return;                                       // тишина
  if (roll === 4) return addProgress(-2);                      // дезинформация
  if (roll <= 7) return spawnEncounter(room, 0);               // встреча
  if (roll === 8) return spawnEncounter(room, -3);             // опасная
  if (roll === 9) {                                            // феномен
    const f = d6();
    if (f <= 2) return addProgress(1);
    if (f <= 4) {
      let dir = (d10() <= 7) ? room.depth + 1 : room.depth;
      if (stripeFull(dir)) dir = (dir === room.depth + 1) ? room.depth : room.depth + 1;
      if (!stripeFull(dir)) createStub(room, dir);
      return;
    }
    changeHp(-2); checkDeath(); return;                        // пыльная мгла
  }
  if (roll <= 11) return spawnItem(room, d6());                // находка
  addProgress(room.depth >= 10 ? 6 : room.depth >= 6 ? 5 : 4); // книга по теме
}

function spawnEncounter(room, reactionMod) {
  if (room.creature) return;
  const row = Math.max(1, Math.min(d6() + Math.floor(room.depth / 2), 12));
  const r = roll2d6() + reactionMod;
  const reaction = r <= 3 ? 'hostile' : r <= 6 ? 'wary'
                 : r <= 9 ? 'neutral' : 'friendly';
  room.creature = makeCreature(row, reaction);     // hp, dmg из таблицы 4.6
}

function searchAction() {                          // «Осмотреться»
  const room = currentRoom();
  if (room.special) {
    addProgress(room.depth >= 10 ? 5 : room.depth >= 6 ? 4 : 3); // сперва progress
    if (d20() >= 15) spawnItem(room, d6());        // затем шанс предмета
  } else {
    const r = d20();
    if (r >= 15) spawnItem(room, d6());
    else if (r >= 9) addProgress(room.depth >= 6 ? 2 : 1);
  }
  room.searched = true;                            // навсегда
  endTurn(true);
}

function restAction() {                            // «Отдохнуть»
  changeHp(2);                                     // не выше HP_MAX
  endTurn(true, true);                             // «шумная» проверка встречи
}

function fightAction() {                           // «Сражаться», один раунд
  const c = currentRoom().creature;
  c.hp -= d6() + (hasItem('paper_knife') ? 2 : 0);
  if (c.hp <= 0) {                                 // добыча
    const loot = d6();
    if (loot >= 4) spawnItem(currentRoom(), d6());
    if (loot === 6) addProgress(1);
    currentRoom().creature = null;
  } else if (c.reaction !== 'hostile') {
    c.reaction = 'hostile';                        // в этом раунде не отвечает
  } else {
    dealToPlayer(c.dmg);                           // ответ (оберег: 0)
  }
  endTurn(false);
}

function talkAction() {                            // «Говорить»
  const c = currentRoom().creature;                // не hostile, не mute
  const mod = { friendly: 4, neutral: 0, wary: -2 }[c.reaction];
  if (d20() + mod >= 12) {
    if (!c.rewardGiven) {
      if (c.knowing) addProgress(3);
      else if (countUnhintedStubs() > 0) giveHint(); // stub.hinted = true
      else addProgress(1);                           // все заглушки уже hinted
      c.rewardGiven = true;
    }
    c.reaction = improveReaction(c.reaction);
  } else {
    c.reaction = worsenReaction(c.reaction);       // до hostile, без удара
  }
  endTurn(false);
}

function giveHint() {                              // подсказка (4.6)
  let cand = adjacentStubs(currentRoom()).filter(s => !s.hinted);
  if (cand.length === 0) cand = allStubs().filter(s => !s.hinted);
  cand.sort((a, b) => a.id - b.id);
  cand[rollRange(cand.length) - 1].hinted = true;  // кандидаты всегда не-hinted
}

function fleeAction() {                            // «Бежать»
  const c = currentRoom().creature;
  const auto = consumeLanternIfActive();
  if (auto || d20() >= 10) {
    let target = getNode(state.player.lastRoom);   // существо остаётся
    if (target.creature && target.creature.reaction === 'hostile') {
      const alt = currentRoom().exits              // защита от пинг-понга
        .map(id => getNode(id))
        .filter(n => n.kind === 'room' && !n.creature)
        .sort((a, b) => a.id - b.id);
      if (alt.length > 0) target = alt[0];
    }
    moveTo(target.id);
  } else {
    dealToPlayer(c.dmg);                           // свободная атака
  }
  endTurn(false);
}

function checkWin() {
  return state.player.progress >= state.player.goal.threshold
      && state.player.maxDepth >= state.player.goal.minDepth
      && state.player.position === 0               // узел входа: id 0
      && state.player.hp > 0;
}

function endTurn(extraCheck, noisy) {              // noisy: true только у «Отдохнуть»
  state.player.turn += 1;
  if (state.player.hp <= 0) return showEnd('lose');
  if (checkWin()) return showEnd('win');
  const due = state.player.turn % 3 === 0 || extraCheck;
  const room = currentRoom();
  if (due && room.depth > 0 && !room.creature) {
    const chance = noisy ? Math.min(3 + Math.floor(room.depth / 4), 7)
                         : Math.min(1 + Math.floor(room.depth / 4), 5);
    if (d20() <= chance) spawnEncounter(room, 0);
  }
  saveGame();
  render();
}

function moveTo(roomId) {                          // и клик по узлу, и бегство
  const from = currentRoom();
  const room = getNode(roomId);
  if (room.visited && room.depth >= from.depth) {
    state.player.wanderCount += 1;
    if (state.player.wanderCount >= 5) { addProgress(-1); state.player.wanderCount = 0; }
  }
  if (!room.visited) state.player.wanderCount = 0;
  state.player.lastRoom = from.id;
  state.player.position = room.id;
  room.visited = true;
  state.player.maxDepth = Math.max(state.player.maxDepth, room.depth);
  pickupItems(room);                               // автоподбор с пола
}

function addProgress(n) {
  state.player.progress = Math.max(0, state.player.progress + n);
  if (n > 0) state.player.wanderCount = 0;
}
```

Сцепка действий: клик по заглушке = `generateRoom(stub)`; если она вернула
`null` (игрок погиб от события при генерации — экран `lose` уже показан),
обработчик немедленно завершается без `moveTo` и `endTurn`; иначе
`moveTo(room.id)`, затем `endTurn(false)`. Клик по открытой комнате =
`moveTo(id)`, затем `endTurn(false)`. «Осмотреться» завершается
`endTurn(true)`, «Отдохнуть» — `endTurn(true, true)` («шумная» проверка
встречи, 4.10). «Говорить», «Сражаться», «Бежать» — `endTurn(false)`.
Использование предмета: применить эффект; проверить смерть — при
срабатывании дальнейшие шаги не выполняются; проверить победу — при
срабатывании дальнейшие шаги не выполняются; иначе `saveGame()` и
`render()` — без инкремента `turn` и без проверки бродячей встречи
(зеркально шагам 3-4 порядка из 4.2).

`checkDeath()` (секция INPUT / ACTIONS): если `state.player.hp <= 0` —
вызывает `showEnd('lose')` и возвращает `true`, иначе `false`. После смерти
обработка клика прерывается: `generateRoom` сразу после `resolveEvent`
проверяет `state.player.hp <= 0` и возвращает `null` (шаг 5 — гарантия
фронтира — не выполняется), а обработчик клика по заглушке при `null` не
вызывает ни `moveTo`, ни `endTurn`. Состояние мира после смерти не меняется,
`showEnd('lose')` вызывается ровно один раз (8.20).

Числовые литералы псевдокода совпадают с константами CFG (12 — `TALK_DC`,
10 — `FLEE_DC`, `% 3` — `ENCOUNTER_PERIOD`, `>= 5` — `WANDER_LIMIT`,
`>= 6` — `DEEP_BONUS_DEPTH`, `>= 10` — `DEEP_BONUS_DEPTH_2`, `+2` у отдыха —
`REST_HEAL`, 20 — `HP_MAX`); в коде вместо таких литералов обязательны
имена CFG.

### 6.3. Секции скрипта

Скрипт делится на десять секций комментариями-разделителями ровно такого
вида (линия из `=`, номер и имя, линия из `=`); все десять обязаны
присутствовать в этом порядке, других таких разделителей в файле нет:

```
1. CONSTANTS / DATA   2. RNG       3. STATE      4. GENERATION
5. GRAPH / LAYOUT     6. RENDER    7. INPUT / ACTIONS
```

Правила: каждая функция лежит строго в своей секции (реестр — 6.12);
в `CONSTANTS / DATA` — только `const`-объявления (литералы и
`Object.freeze`), никакой логики; данные раздела 5 — только там.

### 6.5. Схема state

Ровно одна глобальная переменная верхнего уровня: `let state = null;`
(секция STATE). Сейв — это `JSON.stringify(state)` без преобразований,
поэтому в state запрещены функции, `undefined`, `Map/Set`, циклические
ссылки и DOM-узлы. Полная схема (значения — иллюстративный пример):

```jsonc
{
  "meta": { "version": 1 },      // != CFG.SAVE_VERSION => сейв игнорируется

  "rng": {
    "seed": 482931,              // uint32, неизменен всю партию
    "counter": 137               // число уже сделанных чтений rand();
                                 // лежит в сейве => загрузка продолжает
                                 // ту же последовательность бросков
  },

  "player": {
    "hp": 14,                    // 0..20; 0 = поражение
    "progress": 12,              // >= 0
    "goal": { "id": "medium", "threshold": 20, "minDepth": 6 },
    "inventory": ["bandage", "paper_knife"],  // массив id ITEMS, до 6
                                 // элементов; дубликаты — отдельные элементы
    "position": 4,               // id узла игрока, всегда kind "room"
    "lastRoom": 2,               // id комнаты, откуда пришёл (цель бегства);
                                 // старт: 0
    "turn": 23,
    "maxDepth": 5,               // наибольшая посещённая глубина
    "wanderCount": 1,            // счётчик блуждания (4.7)
    "lanternActive": false,      // активирован фонарь (4.8)
    "wardActive": false          // активирован оберег (4.8)
  },

  "world": {
    "nodes": [ /* узлы графа, схема ниже */ ],
    "edges": [ { "a": 0, "b": 1 } ],  // ненаправленные, a < b, без дублей
    "nextId": 9                  // id только растут, не переиспользуются
  }
}
```

Схема узла (`world.nodes[i]`):

```jsonc
{
  "id": 4,
  "depth": 2,              // неизменна
  "kind": "room",          // "room" | "stub"
  "locRow": 9,             // 1..30, строка LOCATIONS; у stub null
  "detRow": 12,            // 1..30, строка DETAILS; у stub null
  "special": false,        // SPECIAL_ROWS.includes(locRow); у stub false
  "searched": false,       // комната осмотрена (навсегда)
  "visited": true,         // игрок был хотя бы раз; у stub false
  "hinted": false,         // только у stub: «многообещающая» (4.6)
  "exits": [1, 7],         // id соседей, зеркало world.edges (кэш addEdge)
  "creature": null,        // или { "row": 6, "hp": 5, "reaction": "neutral",
                           //        "rewardGiven": false }
                           // имя/dmg/knowing/mute берутся из CREATURES[row-1]
  "items": [],             // id предметов на полу (если инвентарь был полон)
  "x": 550, "y": 300       // назначаются один раз, не пересчитываются
}
```

Узел входа: `id 0, depth 0, kind "room", locRow null, detRow null,
special false, visited true`, имя для рендера — строка словаря
`map_entrance_label` («Вход»), тег `entrance`. Имя и описание обычных комнат
не хранятся в узле, а выводятся хелперами `roomName(node)` / `roomDesc(node)`
из таблиц по `locRow`/`detRow` (таблицы заморожены, дрейфа нет).

Журнал в state НЕ хранится: это эфемерный DOM; после загрузки сейва журнал
начинается с записи «Игра загружена.».

### 6.6. Seeded RNG (код нормативен дословно)

Вызов `Math.random` запрещён — поиск по файлу даёт 0 совпадений.

```js
function mulberry32(a) {
  return function () {
    var t = a += 0x6D2B79F5;
    t = Math.imul(t ^ t >>> 15, t | 1);
    t ^= t + Math.imul(t ^ t >>> 7, t | 61);
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}

// Единственный источник случайности. Значение детерминированно зависит
// только от пары (seed, counter); counter лежит в state и попадает в сейв,
// поэтому загрузка продолжает ту же последовательность бросков.
function rand() {
  state.rng.counter += 1;
  var h = (state.rng.seed ^ Math.imul(state.rng.counter, 0x9E3779B9)) >>> 0;
  return mulberry32(h)();
}

function roll(sides) {                 // бросок dN: целое 1..sides
  return 1 + Math.floor(rand() * sides);
}

function rollRange(n) {                // целое 1..n, ровно одно чтение
  return roll(n);                      // даже при n = 1
}
```

Соответствие псевдокоду раздела 4.11: `d6() = roll(6)`, `d10() = roll(10)`,
`d12() = roll(12)`, `d20() = roll(20)`, `roll2d6() = roll(6) + roll(6)`
(два чтения, именно в таком порядке). Любая случайность игры — только через
эти функции; рендер, журнал и UI не вызывают их никогда.

Парсинг seed (`parseSeed(text)`, секция SCREENS): строка из `#seed-input`,
обрезанная до 32 символов и очищенная `trim()`. Пустая строка —
`1 + (Date.now() % 999999)`. Строка только из цифр — `parseInt(text, 10) >>> 0`.
Любая другая — свёртка в uint32: `h = 2166136261`, затем по каждому символу
`h = (Math.imul(h, 31) + code) >>> 0`. Итоговое число становится
`state.rng.seed` и показывается в статусе.

### 6.7. Раскладка карты

Координаты узла назначаются один раз при создании и никогда не
пересчитываются (никакого force-layout).

- Полоса глубины `d`: прямоугольник от `y = d * CFG.BAND_H` высотой
  `CFG.BAND_H`; центр узлов полосы — `bandY(d) = CFG.MAP_PAD_Y + d * CFG.BAND_H`
  (60 + 120d). Вход (depth 0) — верхняя полоса, рост вниз.
- Слоты: в полосе ровно 10 слотов с индексами 0..9;
  `slotX(s) = CFG.MAP_PAD_X + s * CFG.SLOT_W` (50 + 100s, диапазон 50..950).
  Один слот — не более одного узла. Обратное преобразование:
  `slotOf(node) = Math.round((node.x - CFG.MAP_PAD_X) / CFG.SLOT_W)`.
  Занятость полосы — скан `world.nodes` нужной глубины.
- Вход (id 0) — слот 5 полосы 0 (x = 550).
- Назначение слота новому узлу (`assignCoords(node, parent)`): желаемый слот
  `want = slotOf(parent)`; перебор кандидатов в порядке `want, want+1,
  want-1, want+2, want-2, ..., want+9, want-9`, значения вне 0..9
  отбрасываются; первый свободный слот полосы `node.depth` берётся,
  `node.x/y` записываются навсегда.
- Ёмкость: `stripeFull(d)` истинно, когда в полосе `d` уже
  `CFG.MAX_NODES_PER_DEPTH = 10` узлов (комнат и заглушек). Все создатели
  заглушек (шаг 3 генерации, феномен «Сдвиг», гарантия фронтира) проверяют
  `stripeFull` ДО создания (правила подмены направления — 4.4); поскольку
  лимит равен числу слотов, `nearestFreeSlot` при этом всегда находит место.
- Рёбра: между узлами разных полос (включая разницу глубин больше 1 —
  такое ребро возможно от гарантии фронтира, 4.4 шаг 5) — кубическая кривая
  с вертикальными касательными `M x1 y1 C x1 (y1+60), x2 (y2-60), x2 y2`
  (первый — узел с меньшим y; 60 = BAND_H / 2); формула применяется без
  изменений при любой разнице глубин. Внутри одной полосы (заглушка
  «вбок») — пологая дуга `M x1 y1 Q (x1+x2)/2 (y1+40), x2 y2` (провисает
  вниз и не сливается с промежуточными узлами полосы). Рёбра не
  интерактивны и рисуются под узлами (группа `#edges` раньше `#nodes`).

### 6.8. Рендер

Один вход — `render()`: каждый обработчик действия после мутации state
вызывает `render()` (через `endTurn` либо напрямую для свободных действий).
Никакого точечного патчинга — полная пересборка.

- `renderMap()` полностью очищает `#bands`, `#edges`, `#nodes`
  (`replaceChildren()`) и строит их заново из `state.world`. Размеры: при
  каждом рендере `maxBand = max(node.depth)` по всем узлам (включая
  заглушки); `H = (maxBand + 1) * CFG.BAND_H`; на `#map` выставляются
  `width="1000"`, `height="${H}"`, `viewBox="0 0 1000 ${H}"` — масштаб 1:1,
  без зума.
- Прокрутка: `#map-wrap { overflow: auto; }`; у SVG `display: block;
  margin: 0 auto` — при достаточной ширине карта центрируется, при
  нехватке ширины прокручивается горизонтально внутри `#map-wrap`, поэтому
  все узлы достижимы при любой ширине окна. В конце `render()` контейнер
  прокручивается к текущему узлу:
  `wrap.scrollTop = node.y - wrap.clientHeight / 2`.
- Клики: ровно ОДИН слушатель на `#nodes` (делегирование); по
  `closest('g[data-id]')` извлекается id и вызывается `onNodeClick(id)`.
  Каждый `<g>` узла несёт `data-id="<node.id>"`. Слушатели на отдельные
  узлы не вешаются.
- Панели — обычный DOM: `renderPanel()` перезаписывает `#status`,
  `#room-panel`, `#inventory`, `#actions`. Динамический текст — только
  `textContent` / `createElement`; `innerHTML` — только для статических
  шаблонов без подстановок.
- Журнал: `log(type, text)` добавляет запись В КОНЕЦ `#log`, удаляет лишние
  сверх `CFG.LOG_MAX = 50` с начала и безусловно прокручивает контейнер вниз
  (`el.scrollTop = el.scrollHeight`). Журнал append-only, в `render()` не
  участвует и в state не хранится.

### 6.9. Сейв / лоад / экраны

- Хранилище: `localStorage`, единственный ключ `CFG.SAVE_KEY`.
- `saveGame()`: `localStorage.setItem(CFG.SAVE_KEY, JSON.stringify(state))`
  в `try/catch`; при ошибке — молча пропустить и записать в журнал
  предупреждение (тип `system`).
- Точки автосейва: шаг 6 `endTurn` (каждое действие стоимостью 1 ход),
  конец каждого свободного действия (использование предмета), если оно не
  завершило партию (при победе или смерти `showEnd` уже стёр сейв и
  автосейв не выполняется, сцепка 4.11), `startNewGame` сразу после
  создания state. Других точек нет.
- Сейв стирается (`removeItem`): при показе экранов `win` и `lose`
  (`showEnd`), при подтверждённой сдаче, по кнопке «Сбросить сейв» и в
  начале `startNewGame` (старый сейв перезаписывается новым).
- `loadGame()`: читает ключ, `JSON.parse` в `try/catch`; возвращает `false`,
  если ключа нет, JSON битый или `parsed.meta.version !== CFG.SAVE_VERSION`
  (сейв игнорируется, но не удаляется). При успехе `state = parsed`,
  `true`.
- `init()` (последняя строка скрипта — вызов `init();`): навешивает все
  обработчики, ставит `window.DBG`; затем `loadGame()` — при успехе сразу
  экран `game`, запись журнала «Игра загружена.» и `render()`; иначе экран
  `start`. Отдельной кнопки «Продолжить» на стартовом экране НЕТ — живой
  сейв открывается автоматически.
- Кнопки: `#btn-start` — новая партия (читает seed и пресет, далее
  `startNewGame`); `#btn-new-game` (topbar) — показывает экран `start`, сейв
  не трогает; `#btn-reset-save` — стирает сейв и показывает `start`;
  `#btn-win-restart` / `#btn-lose-restart` — показывают `start`.
  Подтверждение есть только у «Сдаться» (раздел 7.6).

### 6.10. Debug-хуки

В `init()` на `window` вешается объект `DBG` — единственный, помимо
`state`, намеренный глобальный идентификатор. Хуки не пишут сейв и не
двигают `rng.counter`:

```js
window.DBG = {
  addProgress: function (n) { state.player.progress = Math.max(0, state.player.progress + n); render(); },
  hurt:        function (n) { state.player.hp -= n; if (state.player.hp <= 0) { showEnd('lose'); } else { render(); } },
  teleport:    function (id) { var nd = getNode(id); if (nd && nd.kind === 'room') { state.player.position = id; render(); } },
  reveal:      function () { state.world.nodes.forEach(function (n) { n.visited = true; }); render(); },
  god:         function () { state.player.hp = 999; render(); }
};
```

### 6.11. Бюджет строк и правила качества

Ориентир объёма: 1500-2500 строк, целевое значение около 1900. Распределение
(выход за верхнюю границу секции — сигнал упростить её, а не раздуть соседнюю):

| Часть файла | Строки |
|---|---|
| `<head>` + `<style>` | 200-260 |
| Разметка `<body>` | 60-110 |
| 1. CONSTANTS / DATA | 380-560 |
| 2. RNG | 20-30 |
| 3. STATE | 40-80 |
| 4. GENERATION | 160-240 |
| 5. GRAPH / LAYOUT | 80-130 |
| 6. RENDER | 240-340 |
| 7. INPUT / ACTIONS | 220-320 |
| 8. SAVE / LOAD | 40-70 |
| 9. SCREENS | 80-140 |
| 10. INIT (+ DBG) | 30-60 |

Правила качества (нормативные):

1. `'use strict';` первой строкой скрипта. Одна глобальная переменная —
   `let state`; кроме неё на верхнем уровне только `const`-данные секции 1 и
   function declarations; `window.DBG` — единственное присваивание в window.
2. Данные отдельно от логики: весь контент раздела 5 — только в
   CONSTANTS / DATA; функции читают таблицы по индексам. Русские строки UI —
   только из словаря `UI` (раздел 7.10) и словаря шаблонов журнала
   `LOG_TEMPLATES` (раздел 7.7), объявленных там же, в данных.
3. Чистота секций: GENERATION и GRAPH / LAYOUT не трогают DOM; RENDER читает
   state, но не мутирует; мутируют state только GENERATION, INPUT / ACTIONS,
   SAVE / LOAD (загрузка) и STATE (фабрика). Исключение: вызов
   `log(type, text)` разрешён из любой секции и не считается работой с DOM;
   для GENERATION и GRAPH / LAYOUT под запретом остаётся только прямое
   создание, изменение и чтение DOM-элементов.
4. Случайность — только `rand` / `roll` / `rollRange`; `Math.random`
   отсутствует.
5. Идентификаторы, ключи, классы, id элементов — английские; русский — только
   в строковых значениях и комментариях.
6. `textContent` для динамики; `innerHTML` — только статические шаблоны.
7. Никаких `setTimeout` (единственное исключение — снятие класса `is-new`,
   раздел 7.8), промисов, `async`, таймеров игрового цикла — ход полностью
   синхронный.
8. Функция не длиннее 60 строк, вложенность не глубже 3, ранние `return`.
9. Эмодзи запрещены везде; иконки — SVG-примитивы или буквы.

Флейворным шрифтом набираются: заголовки экранов, имена и вопросы пресетов,

### 7.5. Карта: узлы, рёбра, подписи

Геометрия — раздел 6.7 (полосы 120px, слоты 0..9, SVG 1000px шириной).

- **Полоса глубины**: `<rect>` на всю ширину SVG, заливка чередуется
  (`--bg-stripe-a` чётные, `--bg-stripe-b` нечётные). В левом верхнем углу
  полосы (x = 12, y = верх полосы + 16) подпись «ГЛУБИНА {N}» (11px, верхний
  регистр, `--text-faint`).
- **Узел-комната**: `<g data-id>` из невидимого хит-круга `r = 22`
  (`fill: transparent`), основного круга `r = 16` (заливка — цвет тега,
  обводка `1px` `--border`), буквы тега по центру (13px, bold, UI-шрифт,
  цвет `#16120e`) и подписи под узлом (y = центр + 30, по центру, 11px,
  `--text-muted`; у текущей комнаты — `--text`). Подпись — имя локации,
  обрезанное до 14 символов с многоточием. Hover-тултипов и `<title>` нет —
  подписи видны всегда.
- **Заглушка**: круг `r = 14`, `fill: none`, обводка
  `stroke: var(--node-stub); stroke-width: 1.5; stroke-dasharray: 4 3`,

  `r = 22`. **Hinted-заглушка** (4.6): то же, но обводка и «?» цвета

- **Текущая позиция**: единственный `<g id="player-marker">` с кольцом
  `r = 21`, `fill: none`, `stroke: var(--ring-current)`,

- **Посещённые узлы**, кроме текущего: заливка круга `fill-opacity: 0.55`

- **Рёбра**: `stroke: var(--edge); stroke-width: 2; fill: none`; форма —
  6.7. Ребро, ведущее к заглушке, — дополнительно `stroke-dasharray: 4 4`.

### 7.6. Взаимодействие

Единственное устройство ввода — мышь. Клавиатурного управления нет;
единственное исключение — Enter в `#seed-input` (клик по `#btn-start`).

- **Доступный узел** = соединён ребром с текущим узлом И переход в него
  разрешён матрицей 4.2 (hostile запрещает все переходы, wary — переходы в
  заглушки). Доступные узлы получают класс `clickable`: курсор `pointer` и
  hover-подсветка — кольцо `r = 20`, `stroke: var(--accent-gold)`,
  `stroke-width: 2`, появление за 100ms (transition по opacity).
- Недоступные узлы и текущий узел не реагируют ни на hover, ни на клик.
- Клик по доступной заглушке — генерация комнаты и переход; по доступной
  комнате — переход (без перегенерации). Логика ничего не блокирует на время
  анимаций: они чисто косметические.
- Кнопки `#actions` — по матрице 4.2. Подтверждение «Сдаться» — инлайн, без
  модалок: по клику содержимое `#actions` заменяется на текст «Покинуть
  партию? Сохранение будет удалено.» (13px, `--text-muted`) и две кнопки —
  «Да, сдаться» (danger) и «Отмена» (обычная). «Да, сдаться» стирает сейв и
  показывает экран `start`; «Отмена» возвращает прежние кнопки. Сдача — не
  поражение: экран `lose` только при hp 0.
- Клик по предмету в `#inventory` — `useItem(slotIndex)` (свободное
  действие, 4.8).

### 7.7. Журнал

Показываются последние 50 записей (старые удаляются из DOM); новые
добавляются вниз; после каждой записи контейнер безусловно прокручивается в
самый низ. В state журнал не хранится (6.5).

Формат записи: `{номер хода} | {текст}`. `{номер хода}` — значение
`state.player.turn` в момент вызова `log()`; для действий стоимостью 1 ход
все записи делаются до инкремента `turn` в `endTurn`, поэтому записи первого
действия идут с номером 0. Номер хода — колонка 32px,
выравнивание вправо, `--text-faint`; текст — 13px, UI-шрифт, `--text`
(у типа `system` — `--text-muted`); блок записи — `padding: 4px 8px`, левая
рамка `3px solid` цвета типа, отступ между записями 2px. Четыре типа:

| Тип | Цвет рамки | Что логируется |
|---|---|---|
| `combat` | `--danger-text` | удары, урон, добыча, бегство |

| `progress` | `--success` | любые изменения progress, подсказки |

### 7.8. Анимации

Разрешены только CSS transitions длительностью не более 300ms;
`requestAnimationFrame` запрещён; игрового цикла нет. Закрытый список:

1. Появление нового узла: элемент добавляется с классом `is-new`
   (`opacity: 0; transform: scale(0.6)`, `transform-box: fill-box`,
   `transform-origin: center`), через `setTimeout(..., 20)` класс снимается;
   transition `opacity 250ms ease-out, transform 250ms ease-out`. Это
   единственный допустимый `setTimeout` в файле. Определение новизны:
   перед очисткой `#nodes` `renderMap` собирает `Set` значений `data-id`
   текущих `<g>`; класс `is-new` получают только узлы, чьих id не было в
   этом Set (чтение DOM до `replaceChildren`, без новых глобальных
   переменных). Узел, сменивший kind stub -> room, новым не считается
   (id сохраняется).
2. Перемещение `#player-marker`: `transition: transform 300ms ease-in-out`.
3. Hover-подсветка доступного узла: `transition: opacity 100ms`.
4. Hover кнопок: `transition: background-color 120ms`.

Всё остальное (смена экранов, лог, бары, панели) меняется мгновенно.

### 7.9. Окно

Расчётный минимум — 1280x720. На `body` и `#screen-game`:
`min-width: 1240px; min-height: 680px`; при меньшем окне — обычные
браузерные полосы прокрутки (`html, body { overflow: auto }`), интерфейс не
сжимается. При ширине окна меньше ~1420px (SVG 1000px + панель 380px +
отступы) карта прокручивается горизонтально внутри `#map-wrap` (6.8) — все
узлы, включая крайние слоты 0 и 9, остаются видимы и кликабельны при любой
допустимой ширине. Media queries не используются, адаптивности нет,
обработчик `resize` не нужен. Экраны `start`/`win`/`lose` центрируют свою
колонку по горизонтали и вертикали.

## 8. Разъяснения и edge cases

Сведённый список пограничных случаев. Каждый пункт нормативен.

1. **Clamp строк таблиц.** `d20 + depth > 30` — строка 30; начиная с глубины
   29 любой бросок локации и детали даёт строку 30, это допустимо. Дубликаты
   строк в разных комнатах нормальны.
2. **Вход (узел 0).** Не имеет locRow/detRow/события, не особый
   (`special: false`); осматривается по правилам обычной локации (d20:
   1-8 ничего, 9-14 +1 progress, 15-20 предмет), один раз. На глубине 0 не
   бывает ни бродячих встреч, ни существ вообще — hostile у входа невозможен.
3. **Имя входа** — `UI.map_entrance_label`; в `#room-panel` у входа
   показываются `room_entrance_desc` и строка вопроса цели —
   `{goal.question}` из GOALS по `goal.id` (спецификация — 7.2); детали нет.
4. **Заглушки входа.** Ровно 2, глубины 1, создаются в `newState` без
   бросков направления и без броска числа выходов.
5. **Полные полосы.** Если обе полосы-кандидата (d и d+1) заполнены —
   заглушка не создаётся, молча. Гарантия фронтира (4.4, шаг 5) при этом
   ищет первую незаполненную полосу строго вниз (d+1, d+2, ...).
6. **Гарантия фронтира срабатывает только при нуле заглушек во всём графе**
   — после шагов 3-4 генерации. Она не срабатывает после боя, разговора или
   осмотра.
7. **Hinted.** Бонус +3 применяется к броску события один раз — при открытии
   этой заглушки, поверх глубинного модификатора `floor(depth / 8)`; итог
   выше 12 считается 12. Кандидаты подсказки фильтруются по `!hinted`,
   поэтому повторная пометка той же заглушки невозможна; если все заглушки
   уже hinted, вместо подсказки начисляется `progress += 1` (4.6). После
   материализации флаг роли не играет.
8. **Существо в комнате одно.** Любой источник (`spawnEncounter`) при
   занятой комнате не делает ничего и не бросает кубики выбора существа и
   реакции (проверка `room.creature` — до бросков). Существо хранится в
   узле с текущими hp/reaction/rewardGiven и ждёт возвращения игрока.
9. **Бродячая встреча**: только на шаге 5 `endTurn`, только при `depth > 0`
   и пустой комнате. Проверка после хода с `turn % 3 === 0` (т.е. на ходах
   3, 6, 9, ...) или после «Осмотреться»/«Отдохнуть»; проверка после
   «Отдохнуть» использует повышенный порог `min(3 + floor(depth / 4), 7)`
   (4.10). Свободные действия проверку не вызывают никогда.
10. **Порядок в endTurn жёсткий**: инкремент хода — смерть — победа —
    бродячая встреча — сейв — рендер. Существо, появившееся из бродячей
    встречи, в этот ход уже не действует.
11. **Свободные действия** (клик по предмету): не двигают `turn`, не
    вызывают проверку встречи, но завершаются проверкой смерти, проверкой
    победы (актуально для каталожной карточки у входа), `saveGame()` и
    `render()`; при срабатывании смерти или победы дальнейшие шаги не
    выполняются — сейв уже стёрт в `showEnd` (сцепка 4.11).
12. **Бинты при hp 20** — клик ничего не делает, предмет остаётся.
    Каталожная карточка применима всегда. Второй нож — без эффекта, но
    занимает слот.
13. **Фонарь и оберег**: пока флаг поднят, предмет того же типа не
    показывается в инвентаре как кликабельная кнопка (повторная активация
    невозможна) — его слот рендерится некликабельной строкой
    «{название} (ожидание)» (7.2); сам предмет уже изъят из инвентаря в
    момент активации.
    Оберег гасит только урон ОТ СУЩЕСТВА (раунд боя, свободная атака при
    провале бегства); урон феномена «Пыльная мгла» он не гасит и от него
    не расходуется.
14. **Полный инвентарь**: предмет остаётся в `room.items` и виден только
    через журнал; подбирается `pickupItems` при следующем входе в комнату
    или сразу после освобождения слота, если игрок стоит в этой комнате
    (вызов `pickupItems(currentRoom())` в конце `useItem`).
15. **Бегство** ведёт в `lastRoom` — комнату, из которой игрок пришёл (не
    «вверх»), с одним исключением: если в `lastRoom` стоит hostile-существо,
    цель — соседняя с текущей открытая комната без существа с наименьшим id,
    а при отсутствии таких — всё же `lastRoom` (4.6). `lastRoom` обновляется
    при каждом перемещении, включая сами бегства. Существо из комнаты не
    исчезает и остаётся hostile.
16. **Провал разговора** до hostile не вызывает немедленной атаки; удары
    существо наносит только в ответ на «Сражаться» и на провал «Бежать».
17. **Атака не-hostile существа**: существо становится hostile на шаге 3
    раунда и в ЭТОМ раунде не отвечает; со следующего раунда отвечает.
18. **rewardGiven** — флаг на существе: progress/подсказка выдаются один раз
    за партию на конкретное существо; повторные успешные разговоры лишь
    улучшают реакцию (не выше friendly).
19. **Победа.** `checkWin` вызывается в `endTurn` после каждого действия и
    в конце каждого свободного действия; благодаря условию `position === 0`
    это эквивалентно моментам из 4.9 (вход в узел 0 и изменение progress,
    пока игрок стоит в нём). Никакого автоперехода ко входу нет; подсказка
    в статусе — единственное напоминание.
20. **Смерть приоритетнее победы** (порядок шагов 3-4 в `endTurn`).
    Проверка смерти выполняется немедленно после каждого получения урона.
    Для урона феномена «Пыльная мгла» при генерации действует механизм
    прерывания из 4.11: `resolveEvent` вызывает `checkDeath()` (экран
    `lose`), `generateRoom` сразу после `resolveEvent` при `hp <= 0`
    возвращает `null` без шага 5 (гарантии фронтира), а обработчик клика
    при `null` не вызывает ни `moveTo`, ни `endTurn`. Мёртвый игрок не
    доигрывает оставшиеся шаги генерации: состояние мира после смерти не
    меняется, `showEnd('lose')` вызывается ровно один раз.
21. **Блуждание**: `wanderCount` растёт при переходе в посещённую комнату
    с `room.depth >= from.depth`; движение вверх (к входу) не штрафуется.
    Сброс — при открытии новой комнаты и при любом `addProgress(n > 0)`.
    При достижении 5 — `progress -= 1`, счётчик в 0.
22. **Progress не ниже 0**; hp не выше 20 (лечение обрезается) и не ниже 0
    (для отображения).
23. **maxDepth** только растёт; глубина текущей комнаты может быть меньше.
24. **Сейв стирается** при показе win/lose, при подтверждённой сдаче и по
    «Сбросить сейв» — после конца партии F5 ведёт на экран `start`.
    В остальных случаях F5 продолжает партию с последнего автосейва.
25. **Загрузка**: битый JSON или чужая версия — сейв игнорируется (не
    удаляется), открывается `start`. После успешной загрузки журнал пуст,
    кроме записи «Игра загружена.»; история бросков продолжается благодаря
    `rng.counter`.
26. **Тишина и переходы** — флейвор-строки выбираются детерминированно по
    индексам из 5.8 и НЕ потребляют RNG.
27. **«Говорить» не показывается**: у бессловесных существ (mute), при
    hostile и когда существа нет. «Бежать» — только при hostile.
    «Отдохнуть» — только при hp < 20, пустой комнате и не в узле входа.
    «Осмотреться» — только пока `searched: false` и существо не wary/hostile.
28. **Лимит 4 кнопки** в `#actions` гарантирован матрицей 4.2 (максимум:
    «Осмотреться», «Говорить», «Сражаться», «Сдаться» — в порядке из 7.2);
    предметы — не кнопки действий, они в блоке `#inventory`.
29. **Клик по карте в момент инлайн-подтверждения «Сдаться»** разрешён и
    работает как обычно; при любом следующем `render()` блок `#actions`
    возвращается к обычным кнопкам (подтверждение не «липнет»).
30. **Никаких рёбер между существующими узлами**: граф — дерево, рёбра
    создаются только вместе с новой заглушкой. Скрытых проходов, ключей и
    телепортов в прототипе нет.

## 10. Сценарии самопроверки

Прогони все шесть трасс (мысленно по коду либо в браузере) до сдачи.
Используй «политику первого»: из доступных узлов кликается узел с
наименьшим id, из кнопок нажимается верхняя.

**Трасса 1 — старт.** Новая игра, seed 42, пресет `easy`. Проверь: узлов
ровно 3 (вход id 0 и заглушки id 1, 2); рёбра 0-1 и 0-2; `turn 0`, `hp 20`,
`progress 3`, инвентарь пуст; `rng.counter` равен 0 (старт не бросает
кубиков); кнопки — «Осмотреться», «Сдаться».

**Трасса 2 — три шага вглубь.** Из старта трассы 1 трижды кликни заглушку с
наименьшим id среди доступных (если существо любой реакции мешает переходу
в заглушку — wary или hostile — жми «Сражаться» до победы, затем продолжай;
ходы боя в счёт трёх шагов не идут). Проверь после: `turn >= 3`; журнал
содержит ровно 3 записи «Новая комната...» с глубинами, равными глубинам
открытых заглушек; глубина каждой новой комнаты на 0 или +1 отличается от
родительской (на старте полосы не заполнены, поэтому +2 от гарантии
фронтира невозможен); `maxDepth` равен наибольшей из них; у каждой открытой
комнаты остались зафиксированные locRow/detRow.

**Трасса 3 — детерминизм.** Seed 123, `medium`, 10 ходов «политикой
первого». Скопируй текст журнала. «Сбросить сейв», повтори с теми же
вводами. Журналы обязаны совпасть посимвольно, включая все числа бросков.

**Трасса 4 — сейв/лоад.** Seed 123, `medium`, 5 ходов «политикой первого»,
запомни статус и журнал. F5: экран `game`, статус идентичен, журнал —
«Игра загружена.». Сделай ещё 5 ходов той же политикой: записи, сделанные
действиями 6-10, обязаны посимвольно совпасть с соответствующими записями
трассы 3 (RNG продолжился с `rng.counter`, а не начался заново).

**Трасса 5 — поражение.** Любая партия: в консоли `DBG.hurt(19)` — статус
«HP 1/20», игра продолжается; `DBG.hurt(1)` — немедленно экран `lose` со
статистикой. F5 — экран `start` (сейв стёрт).

**Трасса 6 — победа.** Seed 7, `easy`. Иди вглубь до `maxDepth >= 4`
(встречи решай «Сражаться»; при опасности — `DBG.god()`). В консоли
`DBG.addProgress(20)`. Проверь подсказку «Условие выполнено...» в статусе.
Вернись к входу по открытым комнатам: в момент входа в узел 0 — экран `win`,
в статистике прогресс >= 16 и глубина >= 4. F5 — экран `start`.

Порядок работы — строго такой:

   PHENOMENON_NAMES, ITEMS, CREATURES, GOALS, UI_SILENCE, UI_TRANSITIONS),
   словарь UI (7.10) и словарь шаблонов журнала LOG_TEMPLATES (7.7).
3. **Движок**: RNG (6.6 дословно), фабрика state и хелперы (6.5), сейв/лоад
   (6.9).
4. **Генерация и граф**: generateRoom, события, встречи, предметы, раскладка
   (4.4-4.6, 4.11, 6.7).
5. **Рендер**: карта, панели, инвентарь, журнал (6.8, 7.5, 7.7).
6. **Действия**: матрица 4.2, все действия и endTurn (4.2-4.10, 4.11), экраны
   win/lose, DBG (6.10), init.
7. **Самопроверка**: пройди ВЕСЬ чеклист раздела 9 (все 32 пункта) и все
   шесть трасс раздела 10. Любое расхождение — это баг кода, а не повод
   поправить требование. Исправь и проверь снова. Только после этого сдавай.

Запреты: не менять ни одно число, имя поля, id элемента или ключ данных из
этого промпта; не добавлять механики, экраны, настройки и анимации сверх
описанных; не задавать уточняющих вопросов — промпт полон; не выносить
ничего в другие файлы.

Пять самых критичных инвариантов — проверь их в последнюю очередь ещё раз:

1. **Один RNG-поток.** Вся случайность — `rand`/`roll`/`rollRange` поверх
   пары (seed, counter); порядок потребления бросков — строго псевдокод
   4.11; `rng.counter` лежит в state и в сейве; рендер, журнал и UI кубики
   не бросают. Один seed + одни действия = одна партия, до каждого броска.
2. **Мир необратим.** Открытая комната никогда не перегенерируется; граф —
   дерево с корнем во входе, рёбра не удаляются и не добавляются между
   существующими узлами; не более 10 узлов на полосу; гарантия фронтира
   не даёт библиотеке закончиться; координаты узлов назначаются один раз.
3. **Смерть и победа.** `hp <= 0` — немедленный экран `lose`, приоритетнее
   всего; победа — только `progress >= порога` И `maxDepth >= минимума` И
   игрок в узле 0 И жив, проверяется при входе в узел 0 и при изменении
   progress стоя в нём; после win/lose/сдачи сейв стёрт.
4. **Данные отдельно от логики.** Все таблицы раздела 5, словарь 7.10 и
   шаблоны журнала LOG_TEMPLATES (7.7) — в CONSTANTS / DATA дословно; логика
   читает их по индексам; единственная глобальная переменная — `state`;
   сейв — `JSON.stringify(state)` как есть.
5. **Оффлайн и чистота.** Один файл, ноль внешних ресурсов, единственное
   вхождение `http` — константа `SVG_NS`; без `Math.random`, без `async` и
   таймеров (кроме `setTimeout` снятия `is-new`), без эмодзи, без модалок;
   динамический текст — только `textContent`.
